# 探戈 Done&Go

事情搞定，时间归你。（原名 探戈 留白；「留白」现在是应用里给自己留时间的那部分功能。）

> 把时间还给人。

> **2026-10 重新设计**：产品主线改为“被归还的人生时间，应该流向哪里？”。设计说明见 [docs/REDESIGN-2026-10.md](docs/REDESIGN-2026-10.md)；可直接打开使用的网页版本在 [`web/index.html`](web/index.html)（单文件、无需构建，本地双击即可打开）。

工程版本为 `0.0.0`（见 `package.json`）；文中的 V2 / V3 是阶段名称，不是发布版本号。

探戈 Done&Go不是一张更聪明的待办清单，也不是把日历、提醒和聊天机器人拼在一起的生产力工具。它是一层 **Personal Agency Layer**：让一个人的意图、责任、授权、行动与留白，在同一条可以理解、可以修正、可以核验的时间线上共存。

时间不只是等待被填满的容器。它也是人保有判断、拒绝、暂停和重新选择能力的地方。探戈 关心的不是“还能塞进多少事情”，而是：哪些行动值得进入生活，哪些责任确实由我承担，以及一段没有被安排的时间，能否安静地属于我。

## 探戈 试图回答的问题

当一句请求抵达，系统不应立即把它变成你的任务；当一个建议出现，系统不应把它误写成你的授权；当一次操作完成，系统也不应把“已经发出”伪装成“对方已经收到”。

因此，探戈 把行动拆成一条清晰的链路：

| 阶段 | 它回答的问题 | 系统应保持的诚实 |
| --- | --- | --- |
| 意图 | 我真正想保住什么？ | 意图可以模糊，也可以暂时没有用途 |
| 请求 | 外界究竟说了什么？ | 原话、来源与未知字段必须保留 |
| 责任 | 这件事是否由我接受？ | 请求不等于承诺，收集不等于接受 |
| 方案 | 有哪些完成路径？ | 估计、延期代价与未来负担分开呈现 |
| 预览 | 系统准备改变什么？ | 预览不等于生效，前后差异必须可见 |
| 授权 | 我允许哪些动作？ | 授权是有限的、一次性的、可撤回的 |
| 执行 | 什么已经被实际写入？ | 批准、写入与读回结果分开记录 |
| 外部核验 | 外部世界真的发生了吗？ | 未确认的结果保持未知，不制造成功感 |
| 回顾 | 这次行动留下了什么？ | 保住的时间、延期的责任与监督成本都要算进去 |

“什么也不安排”也是一个合法结果。留白不是缺失，而是被保护的自主空间。

## 核心原则

- 请求不自动成为责任。
- 建议不自动成为授权。
- 预览不自动成为执行。
- 执行不自动等于外部结果已核验。
- 移动责任不等于节省时间。
- AI 的推测不能升级为事实。
- 用户可以拒绝、修正、暂停、撤回和退出。
- 没有用途的时间，不需要被系统强行填充。

这些不是产品口号，而是领域模型、状态转换和界面文案都必须遵守的约束。

## 一套围绕时间主权的界面

V2 的桌面与移动体验围绕 18 个入口组织（桌面 14 屏、移动 4 屏），它们不是孤立的页面，而是一条从意图到行动、再回到个人感受的连续路径。`design/` 下的 18 屏高保真原图是**设计示意**（静态产品设计，见 `design/00_阅读说明.md`），不是产品运行截图，逐屏 1:1 视觉验收尚未完成。本节只保留当前 V2 证据支持的能力表述，每条附证据位置；证据不支持的表述不写入，行为验收未完成的入口集中在「证据边界」中说明。

### 看见时间

- **此刻 · 时间主权**：先看要保护的时段，再看容量缺口。（证据：`evidence/green/s01.txt`；`.omo/evidence/root-iab-closeout-20260913.md`）
- **时间账本 · 责任与边界**：把安排与责任、用户选择的边界分成两条轨道，账本内部一致并保护留白，支持今日/本周/本月切换。（证据：`evidence/green/s02.txt`；`.omo/evidence/mobile-ledger-preflight-20260913.md`；`.omo/evidence/rc12-month-view-20260913.md`）
- **留白时刻 · 不安排也成立**：让没有用途的时间保持安静，不转化为绩效、倒计时或打卡。

### 形成责任

- **收件箱 · 请求不等于承诺**：保留原话、来源、提出者和未知字段，等待本人确认。（证据：`evidence/green/s03.txt`）
- **自适应方案 · 改变方法与分工**：不同完成路径先做方案对照，选择后进入预览而非直接生效。（证据：`evidence/green/s04.txt`；`.omo/evidence/b-original-baseline-20260913.md`；减负与延期入口的逐项验证待完成）
- **变更预览 · 有限授权**：在任何写入之前，展示对象级差异和本次授权范围，批准范围限于当次且不自动执行。（证据：`evidence/green/s05.txt`；`.omo/evidence/root-iab-closeout-20260913.md`）

### 协同与恢复

- **协同工作台 · 有来源的草稿**：把草稿、证据、来源与待判断之处放在一起；不同意也可部分确认，选中草稿可导出。（证据：`evidence/green/s06.txt`；`.omo/evidence/flow01-and-postwrite-20260913.md`；`.omo/evidence/LeuBai-draft-export-20260913.json`）
- **工作现场 · 恢复下一步**：恢复真实检查点并与当前规则比对，不凭空发明进度；支持追加文字与语音备注。（证据：`evidence/green/s07.txt`；`.omo/evidence/capture-checkpoint-closeout-20260913.md`）
- **注意力队列 · 同一份预算**：让内部请求共享可见的注意力预算，预算可以为 0 并保留历史。（证据：`evidence/green/s09.txt`；`.omo/evidence/budget-zero-shared-20260913.md`）

### 保留边界

- **我的边界 · 权限与暂停**：区分读取、准备、写入和外部动作，分类面板与暂停状态可用；写入结果未读回时保持"未确认"。（证据：`evidence/green/s10.txt`；`.omo/evidence/flow01-and-postwrite-20260913.md`）
- **私人上下文 · 来源与推测**：把本人意图、AI 假设和数据来源分开保存；演示推测可驳回且刷新保持，意图可按条导出。（证据：`.omo/evidence/root-iab-closeout-20260913.md`；`.omo/evidence/context-export-intents-20260913.json`）
- **时间回顾 · 如实记录收益核算**：跳过等反馈记录后刷新保持，并提供显式修改入口。（证据：`.omo/evidence/root-iab-closeout-20260913.md`；其余反馈类型逐项验收未完成）
- **同步异常 · 未知与接管**：外部同步失败时保留未知状态；可重新核验（当前经演示适配器实测）或暂用本地计划，选择刷新保持。（证据：`.omo/evidence/root-iab-closeout-20260913.md`）
- **快捷输入 · 意图与约束**：文字、粘贴、链接参数与语音进入同一录入面板，保留来源渠道与原话；语音仅在明确点击时调用浏览器识别，不可用时给出可见回退。（证据：`.omo/evidence/capture-checkpoint-closeout-20260913.md`）

### 让移动端保持克制

- **移动端 · 此刻**：与桌面共用保护时间创建路径：倒置时段拒绝、空用途可保存、跨屏定位同一时段。（证据：`.omo/evidence/protected-create-cross-tab-20260913.md`）
- **移动端 · 一次性授权**：明确允许的动作与排除项，不包含默认的发送、改会或付款；read+draft、estimate-only 等组合已实际执行。（证据：`docs/RELEASE-STATUS.md` RC4/RC10 增量；`.omo/evidence/rc11-current-build-walkthrough-20260913.md`）
- **移动端 · 留白时刻**：与桌面共用同一条留白决定，跨屏与刷新保持。（证据：`.omo/evidence/quiet-cross-device-20260913.md`）

### 证据边界（未写成能力的部分）

- **移动端 · 自适应方案**：最新构建有渲染与容量摘要记录（`.omo/evidence/rc11-current-build-walkthrough-20260913.md`），交互与授权流行为验收未完成，不作为能力表述。
- 18 屏 1:1 视觉终验（C1）、全交互 E2E（C2）、真实邮件收件、真实日历/音乐/麦克风账户、公开部署验收均未完成；当前证据以[发布状态](docs/RELEASE-STATUS.md)和[逐项交付矩阵](docs/DELIVERY-MATRIX.md)为准。

## 技术骨架

探戈 Done&Go 的 V2 工程当前是一个可在本机运行的 React + TypeScript 工程，技术结构服务于上面的边界，而不是用自动化掩盖边界。

- React 19、TypeScript 6、Vite 8。
- 以领域状态、命令和回读结果组织跨页面行为，保留批准、执行、冲突和未知状态。
- 本地优先的数据存储，业务记录保存在当前浏览器 origin 的本地存储中。
- 本地 Node HTTP 服务承载 API 与设置能力，默认只绑定 loopback。
- 本地身份与会话服务使用 SQLite 和 HttpOnly 会话 cookie。
- LLM 设置在本地服务侧解析、测试与保存；API key 不写入前端构建产物，也不回显已保存值。
- 视觉系统以白瓷、留白与水墨为基调：叙事标题使用 Noto Serif CJK SC，功能文本使用 Noto Sans CJK SC，拉丁字符优先使用 Inter。

工程中的关键实现边界包括：保护时段与普通安排分离、请求与已接受责任分离、方案批准与实际写入分离、来源过期与空闲分离，以及外部结果未核验时的未知状态保留。

## 设计语言

探戈 的视觉不把 AI 描绘成一个无所不知的能量中心。它更接近白瓷器物：有结构，有重量，也有让呼吸发生的空处。

浅色背景、细描边、冷银结构与少量状态色共同建立层次。信息蓝表示估计与进行中，确认绿表示已同步、已授权或已保住，温暖棕表示未知、缺口与待确认事项。颜色始终与文字并用，不让颜色或图标独自承担意义。

## 本地运行

需要 Node.js 22.22.2 或兼容版本。

```sh
npm ci
npm run build
npm start
```

然后打开：

```text
http://127.0.0.1:5200
```

该入口同时提供构建页面与本地 API。开发时可以分别运行 `npm run server` 和 `npm run dev`；Vite 默认将 `/api` 转发至本机 5200 端口。

端口可通过 `LEUBAI_PORT` 调整，开发代理可通过 `LEUBAI_API_URL` 指定。业务记录按当前浏览器 origin 保存；更换协议、主机或端口会进入另一份本地存储，不表示旧数据已被删除。

## 验证

```sh
npm run test:unit
npm run lint
npm run build
```

验证层级需要分开理解：纯测试、类型检查、构建、浏览器交互、真实外部账户结果、设备能力和公开部署，并不是同一件事。当前文档中的状态与证据以 [发布状态](docs/RELEASE-STATUS.md) 和 [逐项交付矩阵](docs/DELIVERY-MATRIX.md) 为准。

## 安全与诚实的边界

- `.leubai-local/` 只用于本机设置，已加入 Git 忽略规则；不要把密钥写入源码、前端产物或证据文件。
- 默认服务只接受 loopback 访问，当前项目不应被描述为已经完成的公开多用户 SaaS。
- 真实日历、音乐账户、麦克风、系统分享与完整生产部署，都需要各自的权限、环境和实际验收。
- 演示数据、局部流程通过和本地服务可访问，不等于外部提供商已经连接，也不等于线上结果已经发生。

## 一句话

探戈 不替你安排人生。它只把意图、责任、授权、行动与留白放回同一条时间线上，让技术更聪明地工作，也让人更完整地拥有自己的时间。
