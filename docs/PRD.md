## 1. 产品概述与设计对象

静驻的首要产品对象不是任务数量，而是**用户希望保住的一段时间**。任务、来源、外部承诺、AI 产物与授权全部围绕这段时间组织：先决定“哪段时间要保住”，再讨论由谁、用什么方法完成其余事项。

**设计对象与用户**：面向需要同时管理工作责任与个人时间的个人用户。产品必须服务两种时刻——安排工作时的判断时刻，以及处于保护时段内的安静时刻；两者的界面密度与语气完全不同。

**视觉方向**：白瓷、冰白玻璃、冷银结构与极少量状态色；开放椭环表达“可呼吸的边界”，不用能量球暗示 AI 全知。首页与静驻时刻允许空间感；文档、权限与失败页面优先保证文字与操作可读性。不使用星球、风景或大面积光效铺满功能页面。

**哲学，落实为规则**：
- 不安排也是正常结果；
- 请求不自动成为责任；
- 延期不自动算省时；
- 草稿不自动等于完成；
- 用户可以拒绝、修正、暂停和退出。

任何功能设计若与上述五条冲突，以规则为准。

## 2. 设计规范与令牌

**排版基准**：桌面 1920×1200，内容区从 x=151 开始；主标题 42，正文 17—20，辅助说明 13—16，最终大图按 2× 输出。移动端 480×1040，主标题 31—35，正文 14—18，最终大图按 3× 输出。

**字体分工**（叙事与操作在字形上分开，不允许全部文字变成装饰）：中文叙事标题 Noto Serif CJK SC；中文功能文案 Noto Sans CJK SC；拉丁界面标签优先 Inter；时间数字采用衬线数字排版。

**状态色语义**：颜色永远携带文字；图标与颜色不作为唯一状态表达（详见 §8、§6）。

### s01 此刻 · 时间主权

**设计大图**：`design/01_桌面大图/01_此刻_时间主权.png`（对应图号 01）。

**目的**：首页以“要保护的一段时间”为主对象（今晚 19:00—20:00），同时呈现当前容量缺口（10 分钟）与一个需要用户决定的单一问题，把用户下一步引向“查看可行做法”。

**布局区域**：
- 左侧图标导航栏：此刻 / 时间 / 收件 / 协同 / 回顾 / 边界，底部搜索（⌘K）与头像。
- 顶部品牌行：静驻 / PERSONAL TIME；右侧“概念设计 · 演示状态”徽标与日期（09.12 · 星期六）。
- 主区“时间意图”卡：衬线大字 19:00—20:00；副文案“不自动填入工作。暂时没有用途，也成立。”；暖色警告 pill“当前计划超出容量 10 分钟”；主动作“看看可行的做法 →”与诚实副文案“还没有修改任何安排”；开放椭环视觉。
- 右列决策卡“01 此刻，只需一个决定”：问题“怎样把这十分钟找回来？”；并列 120（可用时间/分钟）与 130（当前投入估计/分钟）；两个候选方向：“准备报告草稿，减少从零开始（预计减少 20 分钟，仍需你检查确认）”与“或者，把行政事项移到明天”。
- 下区“02 没有被悄悄改变的责任”三张责任卡：已确认会议 30 分钟（固定约定 · 不自动移动）、报告交付 60 分钟（19:00 截止 · 标准不变）、行政事项 40 分钟（个人计划 · 可以重新决定）。
- 页脚：覆盖范围声明（工作日历、任务清单、指定文件；其他生活安排仍需确认）与“界面为独立演示状态；不代表已连接、已执行或真实收益”。

**数据模型**：
- `protectedBlock`：`{ start: "19:00", end: "20:00", purpose: null, lockedBy: "localRule" }`（用途允许为空）。
- `capacity`：`{ availableMinutes: 120, plannedMinutes: 130, gapMinutes: 10 }`。
- `commitments[]`：`{ title, minutes, kind: "固定约定" | "截止任务" | "个人计划", mobility: "不可自动移动" | "可重新决定" }`。
- `decision`：`{ question, options: [{ label, expectedReductionMinutes?, note }] }`；状态字段 `modifiedAnything: false` 支撑“还没有修改任何安排”。

**交互**：主动作与右列候选方向均进入 s04 方案页；责任卡只读展示移动性，不提供“悄悄移动”入口；搜索唤起全局快捷输入（s14）。

**状态**：
- 空态：未设置保护时段时给出发起保护的入口；无容量缺口时显示“容量充足”，不得编造缺口。
- 失败/过期：来源未同步时账本数据标注过期并保留上次数据，不回退为空列表（§05）。
- 边界：缺口为 0 或负值时如实显示；未连接真实来源时演示数据必须带“演示状态”徽标。

**验收标准**：
1. 首屏视觉主对象是保护时段 19:00—20:00，而不是任务完成量。
2. 容量缺口 10 分钟以文字 + 暖色 pill 双重呈现。
3. 页面不出现“已优化 / 已节省”字样；主动作旁可见“还没有修改任何安排”。
4. 三张责任卡各自显示移动性属性，且没有批量移动入口。

**必须保留的边界**：没有执行变更不能写成已优化；不自动填入工作；暂时没有用途也成立。

### s02 时间账本 · 责任与边界

**设计大图**：`design/01_桌面大图/02_时间账本_责任与边界.png`（对应图号 02）。

**目的**：以“安排与责任”和“你选择的边界”两条轨道呈现同一天，使 19:00 的容量冲突直接可见，并保证静驻不能被自动侵占。

**布局区域**：
- 标题区：“时间有去向，也有边界。”；副文案“固定约定、可变计划与静驻分开记录；空白不自动意味着可占用。”
- 日历卡：日期 9 月 12 日，今日/本周切换，时区 UTC+8；时间轴 17:00—20:30 分双列：左轨“安排与责任”依次为已确认会议（30 分钟 · 固定约定，带锁形图标）、报告交付（预计投入 60 分钟，pill“19:00 前提交”）、行政事项（40 分钟 · 暂定计划），其越界部分以斜线阴影 + “超出边界 10 分钟”警告呈现；右轨“你选择的边界”含胶囊“未提前安排的时间 ≠ 必须工作”与“受保护的静驻 19:00—20:00”卡（“没有用途，也不接受自动填充。”）。
- 轴底说明：“需要改变完成路径，或由你重新决定可变事项。”
- 右列“01 今天的容量”：120 分钟可用 / 130 分钟当前预计投入 / 10 分钟容量缺口（暖色）。
- 右列“02 每件事都保留来源”：工作日历 17:00 已同步；任务清单 17:00 已同步；其他安排 未覆盖（暖色）。
- 右列收束卡：“移动，不等于节省。如果把工作移到明天，今天会更宽裕，但未来责任仍在。”＋主动作“查看可行方案 →”。

**数据模型**：
- `dayTimeline`：`{ date, timezone, lanes: { responsibility: TimelineEvent[], boundary: ProtectedBlock[] } }`。
- `TimelineEvent`：`{ title, start, end, minutes, kind: "固定约定" | "暂定计划" | "截止任务", sourceRef, overflowMinutes? }`。
- `sourceRegistry[]`：`{ name, lastSyncAt, coverage: "已同步" | "过期" | "同步失败" | "未连接" | "未覆盖" }`。
- `conflict`：`{ range: "19:00—20:00", gapMinutes: 10, overflowEventId }`。

**交互**：今日/本周切换；事件点开查看来源与状态；越界/冲突区域跳转 s04；暂定计划可由用户重新决定；静驻卡只读，不响应拖拽填充。

**状态**：
- 空态：轨道为空时显示来源说明与手动记录入口，不伪造现成任务（§05）。
- 来源过期/失败：事件保留并标注最后成功同步时间与范围，不当作空闲。
- 边界：计划侵入保护段时以斜线阴影 + 警告呈现；“其他安排 未覆盖”必须显示为未知，不得折算成可用容量。

**验收标准**：
1. 双轨在视觉上可区分，且各自有列标题。
2. 19:00 冲突以越界阴影 + “超出边界 10 分钟”文字同时呈现。
3. “其他安排”行显示“未覆盖”，页面任何位置不把它呈现为空闲。
4. 静驻卡不可被拖拽或自动填充。

**验收标准**：

2. 三项授权与三项排除项同屏可见。

4. “有效范围：本次准备任务”可见，不存在常驻授权入口。

**必须保留的边界**：参数或计划变化使旧批准失效；不可逆外部动作本次不授权；撤销访问只控制后续访问。

**状态**：

**验收标准**：

  2. 🔒 不可擅自改变——现有客户会议——没有自动授予改会或发消息权限。
- 说明行：“下一步只检查冲突。需要改变安排时，再向你展示具体差异。”
- 动作：检查这段时间（主动作，放大镜图标）/ 只保存为意图；快捷键提示“⌘ Enter”；卡底“快速记录 / 自然语言 / 语音 / 分享到静驻 · 同一套语义与授权边界”。

**数据模型**：
- `capture`：`{ verbatim, channel: "快速记录" | "自然语言" | "语音" | "分享", parsed: { intent: { type: "个人时间意图", start, end, timezone, calendarEventCreated: false }, constraints: [{ object: "现有客户会议", rule: "不可擅自改变", granted: [] }] } }`。
- `conflictCheck`：`{ status: "未检查" | "无冲突" | "有冲突", diffs? }`——有冲突时进入差异展示，不直接执行。

**交互**：解析结果可逐字段修改；“检查这段时间”运行冲突检查并按结果展示差异或确认保存；“只保存为意图”仅存意图，不创建日历事件；ESC 关闭不丢失已保存内容之外的输入草稿。

**状态**：
- 解析不确定：展示理解结果并标注可修改，不静默采用。
- 冲突态：与保护时段或客户会议冲突时只展示差异，等待用户决定。
- 空态：输入为空时显示来源、示例与手动记录入口（§05）。

**验收标准**：
1. 意图卡显示“尚未创建日历事件”。
2. 约束卡显示“没有自动授予改会或发消息权限”。
3. 两个动作均不产生任何外部变更。
4. 底部声明四个入口共用同一套语义与授权边界。

**必须保留的边界**：输入一句话不等于泛化授权；下一步只检查冲突，改变安排前展示具体差异；改会、发消息权限不被自动授予。

## 5. 主要流程

### 5.1 保住一段时间

用户表达意图 → 获取经授权的当前事项 → 检查来源覆盖与容量 → 生成不同方法 → 用户选择 → 展示具体变更 → 检查有效授权 → 准备或执行 → 回读结果 → 更新责任与时间账本 → 进入个人时间。

涉及屏幕：s01（意图与缺口）→ s02（容量与来源）→ s04（路径选择）→ s05（授权预览）→ s06（草稿）→ s02/s12（账本与回顾）→ s08/s18（个人时间）。

**规则**：不把“生成计划”“批准计划”“执行成功”“外部结果核验”“本人感到受益”折叠成同一个完成状态；每一步必须显示自身状态词（§6）。

### 5.2 工作被打断后继续

保存检查点 → 重新打开时核对来源版本 → 恢复已确认部分 → 显示一个未决判断 → 用户选择继续、口述、补材料或暂不处理。

涉及屏幕：s07（检查点恢复）→ s06（继续核对）→ s14（口述/快捷输入）。

**检查点必须包含**：产物版本、上次确认的取舍、尚未解决的问题、关联材料与下一步。模型自己的推测不能占据“已确认”位置；恢复界面不得发明进度。

### 5.3 外部请求形成责任

原始请求 → 候选事项 → 用户确认是否接受 → 明确责任范围 → 再讨论截止时间和投入。

涉及屏幕：s14/s03（进入收件箱）→ s03（确认或保留为想法）→ s01/s02（责任入账）。

**规则**：一项请求可以保留为想法，也可以被排除；接受新责任的动作，与对外发送“我来做”的消息必须区分——后者永远属于“每次确认”权限（s10）。

## 6. 状态机

六个对象的状态词即责任边界，不只是视觉标签（§05）：

| 对象 | 状态 | 展示原则 |
|---|---|---|
| 方案 | 候选 / 选中 / 待批准 / 失效 | 未批准不写成已安排；来源变化后提示重新检查 |
| 操作 | 未开始 / 执行中 / 核验中 / 已核验 / 失败 / 未知 | 执行中说明当前动作，不虚构百分比进度 |
| 草稿 | 生成中 / 待检查 / 部分确认 / 已确认 / 已发送 | 状态词是责任边界；未核对内容保持可见 |
| 保护 | 本地规则有效 / 外部写入中 / 外部待核验 / 已覆盖指定渠道 | 不把局部覆盖宣传为全系统保护 |
| 来源 | 已同步 / 过期 / 同步失败 / 未连接 | 显示最后成功更新时间和覆盖范围 |
| 个性化 | 本人表达 / 系统假设 / 被否定 / 过期待复查 | 被否定后不继续隐形套用旧假设 |

**反馈细节**：
- 正常加载使用轻量骨架或状态文字，不做无限旋转的“AI 正在理解你”。
- 失败保留上一份可用数据并标注过期，不回退为空列表。
- 输入为空时显示来源、示例与手动记录入口，不伪造现成任务。
- 悬停显示轻微描边与操作提示；按下减少阴影并做极小位移；键盘焦点使用可见蓝灰外框（`--focus`）。
- 危险操作不只靠颜色区分，必须保留具体文字；停用按钮同时给出不可操作的理由，不能只有低透明度。
- 确认框的关闭和返回不丢失候选方案；若已发生不可逆外部动作，关闭界面不能被解释为撤销；撤销访问只控制后续访问，不承诺收回所有外部副本。

## 7. 时间账本算术规范

以下算术（§06）为设计情境与记账规范，不是实际任务耗时或研究效果数据。

**基准情境**：17:00—19:00 的可用容量为 120 分钟。会议 30、报告预计 60、行政事项 40，合计 130 分钟，存在 **10 分钟缺口**。

**方案 A（改变方法）**：报告先由 AI 准备，预计人工投入 40 分钟，包含用户检查与修改。合计 30 + 40 + 40 = **110 分钟**。“预计减少 20 分钟”是估计，**并非已测量的事实**；实际核对超过估计时必须重新检查容量。页面呈现：预计减少、19:00 前预计总投入（110/120）、仍需本人完成的内容，三行分开。

**方案 B（延期）**：行政事项移至未来，当前合计 30 + 60 = **90 分钟**，但未来仍欠 40 分钟。**不得显示“节省了 40 分钟”**；预计净节省记为“没有发生”，40 分钟记为“明天新增负担”。

**保住时段的记账**：保住 19:00—20:00 这一小时，**不能宣称“AI 节省了一小时”**。保留目标时段与减少人工投入分别记录（s12 三行账目），避免重复记功；净节省在缺少对照与成本核算前一律记为“尚未测量”。

**实现要求**：账本任何汇总视图不得出现跨类合计（保留 + 减少 + 延期）或“省时总数”；延期负担未清偿前持续留在账面。

## 8. 移动端与无障碍

**移动端行为**（§07）：
- 主流程单列，关键动作靠近底部；固定底部按钮不得覆盖正文，字体放大后允许纵向滚动。
- **授权的排除项不能因小屏幕而被隐藏**（s17 三项授权与排除行同屏）。
- 安静界面保留清晰退出入口，不困住用户（s18 的 ×）。

**无障碍实施要求**：
- 所有交互需要语义标签、可见键盘焦点与屏幕阅读顺序。
- 自动排程不能只依赖拖拽；每项时间变更还应提供表单或键盘路径。
- 触控目标按至少 **44 CSS 像素**设计。
- 图标与颜色不作为唯一的状态表达；状态永远伴随文字。

**动效实施规范**：面板入场 160—220 毫秒，确认状态 120—180 毫秒；安静界面的装饰不持续抢注意力；跟随系统“减少动态效果”设置。PNG 本身不包含动效是设计资料的属性，不免除应用实现及验证这些行为的责任。

## 9. 验证策略与验收边界

**证据结构**：每个设计区域、控件、交互、状态与第 4 节验收项都需要稳定需求 ID，并映射到实现位置、用户 C 编号、验证步骤、预期结果及证据文件。既有 `evidence/red/sNN.txt`、`evidence/green/` 可以保留为历史或局部检查证据；文案存在、stub 转绿、测试通过均不能单独替代对应的真实浏览器布局或端到端结果。截图存于 `evidence/screenshots/`，每份新证据记录提交/工作树版本、时间、运行环境、视口、数据模式和用例 ID。缺证据不得标记通过。

**失败先行（RED → GREEN）**：每项行为改变在生产代码修改前，由 GLM 捕获针对真实缺陷的 RED；修改后执行同一案例并保存 GREEN。RED 记录真实输入、前提、预期、实际失败与版本，不能事后虚构；文案 stub RED 只算历史局部证据，不能替代输入变化、状态后果或端到端缺陷的 RED。若已有实现缺少真实先行 RED，明确记录该证据缺口，不倒改历史。

**测试组织**：既有 `tests/groupA.spec.ts`（s01–s05）、`tests/groupB.spec.ts`（s06–s10）、`tests/groupC.spec.ts`（s11–s14）与移动端规格可以作为起点；补齐全控件覆盖与跨屏流程用例。每条用例可覆盖 C1–C5 子集，但总体验收必须覆盖所有要求，且不得用旧编号的通过记录声称用户对应编号已通过。`[data-page="sNN"]` 只是定位标识，不是验收结果。

**设计资料与应用验收分开**：设计规范 §08 声明的图片尺寸、文字出界、重叠及目视审阅，仅描述附件作者的静态设计交付，不是本应用已有运行证据。正式应用须实现来源同步、权限验证、并发变更检查、幂等执行、结果回读与真实撤销语义。应用实际完成情况以本项目 C1–C5 证据为准；本地可控数据、故障注入、真实外部账户、发布环境和用户效果的证据不得互相替代。

## 10. 范围与外部授权边界

V2 的实施范围包含全部 18 屏的布局、文案、交互、共享持久状态、空错非法状态、规定动效与无障碍行为。各屏保留设计示例数据作为可复现的 1:1 对照场景；演示数据模式必须明确标注，业务状态不得仅靠不相连的演示页面模拟。真实来源数据出现时，显示实际覆盖、更新时间和执行状态。

- **外部账户与外部写入**：来源接口、覆盖状态、鉴权前提、同步及执行合同属于本地实现范围，adapter 必须诚实返回已连接、未连接或可控本地结果。连接具体日历、邮件、任务或音乐账户，以及外部写入，需要用户对具体系统、账户、对象与动作的授权；没有该授权时单列真实接入/发布相关验收为 BLOCKED 或 UNKNOWN，不虚报完成，也不据此删除本地功能需求或无限阻断本地验收。应用内批准不能替代账户接入授权。
- **持久化**：用户意图、责任、审批、产物、检查点、规则、账本及“不安排”选择需要按执行合同持久保存与恢复。合成数据不是已连接或真实收益证据；保存成功必须有真实存储结果。
- **收益诚实性**：§7 算术是设计情境。没有测量、监督成本核算与适当对照，不宣称真实净节省、效率提升或用户效果。
- **无障碍与用户效果**：本 PRD 的无障碍要求必须实现并验证；没有完成认证或用户试验时不得声称已认证或有效。这不豁免功能、键盘、触控、字体放大及减少动态效果验证。
- **全系统通知接管**：注意力预算只覆盖已接入请求，不做未经授权的操作系统级通知接管（s09）。
- **发布**：上线级本地交付验证是本次目标；本地功能完整性、adapter 诚实边界与外部未验证项分别报告。实际部署、域名、生产账户与公开发布按用户已给出的具体授权执行，缺失的外部条件逐项呈报，不能把本地构建通过写成已经上线。

## 11. 收尾模块实施细则（2026-09-13）

本节补足业务行为，不替换以上18屏设计与原验收分母。所有保存必须经过同一共享领域状态与持久化确认；视图已显示不等于已经保存。

### 11.1 意图生命周期（S11，关联S04/S14/S17）

- 编辑保留意图ID、原文空白和明确来源，递增修订号；日期、开始/结束时间与时区必须有效，主题允许为空。
- 暂停意图后不得继续生成依赖它的新方案；编辑暂停意图不自动恢复。恢复仅改变当前意图状态，不复活旧批准。
- 编辑/暂停/恢复/删除使相关未执行方案及未消费批准失效，不撤销已存在的责任、操作回执或保护时段。
- 删除须明确确认，清除意图及关联捕获的原文/字段/约束，保留最小墓碑防止再次使用；不删除无关业务历史。
- 每个动作必须绑定本人、确切对象和打开操作时的修订号。明确版本冲突要求重新核对；存储结果未知保留原命令准确重试。

### 11.2 来源停止读取与撤权（S13）

流程为本地停止读取持久化→供应商撤权→独立回执持久化。第一步完成前不联系供应商；以后同步/材料读取在调用供应商前即拒绝。

回执区分 pending、confirmed、failed、unknown、unavailable，逐来源显示申请/回执时间。超时视为unknown，不恢复本地读取，不宣称召回已传出的副本。合成来源始终标记合成演示回执。刷新读出已保存回执；未确认写入保留精确命令，准确重试不重复联系供应商；供应商失败或未接入时保留明确重试/外部账户检查路径。

### 11.3 静驻文字与采集渠道（S08/S14）

- S08“记下一个想法”最多4000字，仅保存开放文字草稿，不解析、不生成意图/责任/计划、不改变静驻选择。最近文字展示最多5条非空、未丢弃、未转换草稿，按更新时间倒序。
- S14文字、voice与share使用同一字段解析和批准边界，渠道与原文持久保存；刷新后仍能定位已保存意图并禁用重复保存。
- 语音只在明确点击后请求浏览器语音服务；先显示可能联网识别说明，转写须本人核对并明确填入，再明确保存。停止口述按钮在监听期间始终可用；卸载取消监听和回调。不支持/拒绝/识别失败均提供可读结果与键盘后备，不伪造识别成功。
- 分享支持显式粘贴及 `/capture?title=…&text=…&url=…` 文本接收。传入内容先展示待确认，不自动保存，不读取链接页面，也不因分享授予改会或发送权限。原生OS分享面板注册与真实设备链路另行验收，URL接收不可冒充系统集成。

### 11.4 检查点附注与规则对照（S07）

- 附注追加本人文字/口述转写，原文最多20000字、非空，保存渠道与时间；不覆盖检查点原始快照、不确认问题、不改写草稿。
- 同一命令重试最多追加一次。写入结果未知保留命令；明确版本冲突保留文字，显示核对最新记录后的重新保存入口，以新命令和最新修订号执行。
- 新检查点记录保存时的授权、自动化开关、每日容量、时区和规则版本；只比较已捕获字段与当前字段，展示保存时/当前双列，不自动应用旧规则。
- 旧检查点缺少规则快照时显示历史未知，不用当前值补造。容量快照必须为正安全整数；损坏快照拒绝载入且保留原始数据。

### 11.5 验收执行约束

浏览器交互、截图及委派QA只用Codex内置浏览器或Ego Lite；独立Playwright/Chromium旧用例不作为执行入口。单元测试、适配器模拟、实际UI、真实供应商、公开部署分别记录。最新候选截图与固定构建记录在 `.omo/evidence/rc-20260913/README.md`，不是全部C1-C5自动通过标记。

### 11.6 保护时段创建与关闭语义（S01/S02/S08/S15/S18）

- “设置一段保护时间”必须显式创建ProtectedBlock，不能以保存Intent或跳转采集页替代。字段为日期、开始/结束时间、IANA时区、可选用途；允许不关联意图、用途为空，不能自动编造主题。
- 非法日期、倒置/不存在的本地时间及未知时区不写入。明确提交仅保存本地保护范围，不创建任务、外部事件或虚构来源覆盖；同命令重试不重复创建。
- 成功必须经过领域状态及持久化读回确认。结果未知保留输入和确切命令，不能把失败改成成功或无限追加新记录。
- S15时间卡携带准确intentId、date、稳定blockId进入S02。账本显示同一保护时段、用途、时区和原意图，日/周切换保留定位；重复、缺失或不匹配的查询拒绝，不静默替换。
- 已确认keepStill后的×只关闭界面，不将决定改写为exit，不取消提示抑制。关闭前核验最新状态与持久化记录；不一致/未知时保留页面及明确重试。未作决定的退出仍如实记录退出，不等同于选择静驻。

### 11.7 部分授权的批准前预检（S17）

读取、草稿、投入估计三个许可的八种组合必须复用领域依赖规则。批准前列出真正可执行动作以及因未授权/缺前置步骤而排除的动作；没有可执行动作时明确禁用。未允许读取时不能创建依赖材料的草稿，即使草稿许可勾选；投入估计可独立获准。按钮描述跟随真实动作，不承诺被排除的草稿。执行后仅显示实际产物与逐项读回，刷新保留已消费批准和同一产物，不重复执行。
