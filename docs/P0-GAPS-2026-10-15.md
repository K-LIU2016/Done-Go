# Done & Go P0 gap closure

核验日期：2026-10-16。范围：本地优先 Web 版本的时间收益口径、AI 文本发送、浏览器存储、导入恢复和个人历史参考。

本文把事实分成四类：VERIFIED（代码或测试直接观察到）、INFERRED（由规范和实现共同支持）、HYPOTHESIZED（仍需实验）、UNKNOWN（当前环境无法确认）。

## P0-1：把“AI 节省时间”从产品承诺改成可验收的个人测量

- **VERIFIED**：只有 quality=accepted 的完成记录进入实际差值；pending、rework 和缺少验收质量的旧记录不会进入收益或个人历史样本。实际用时包含执行、准备、核对和返工，超时保留负值。代码位于 web/index.html 的 TangoTime 模块，单元测试覆盖 19 项中的相关场景。
- **VERIFIED**：少于两条同类、去重、使用 AI、已验收的个人记录时，今日事项和模型能力面板显示“时间收益待实测 · 样本不足”；有足够记录后才显示个人差值范围。
- **VERIFIED**：完成事项时保存计划基线与个人参考快照；后续历史记录不会重写旧任务。
- **INFERRED**：这消除了“场景比例被误读成因果证明”的主要产品风险，但个人差值仍然不是随机对照实验。
- **HYPOTHESIZED**：用户看到“待实测”后，是否仍愿意完成一次 AI 使用并验收，需要真实用户实验验证。

## P0-2：防止密钥和事项文本在不知情时外泄

- **VERIFIED**：API key 不进入 tango-donego.web.v1、导出数据或持久化 AI 配置；启动时发现旧版本 key 会清除并提示用户，同时撤销旧 consent，必须重新勾选后才会发送事项文本。会话 key 只留在内存。
- **VERIFIED**：自定义接口只允许 HTTPS，或 localhost、127.0.0.1、::1 的 HTTP；用户名、密码、控制字符和 javascript: URL 被拒绝。
- **VERIFIED**：未勾选 consent 时不发送事项文本，使用规则解析；设置页明确说明数据留在浏览器、启用 AI 后事项文本会发送到所选接口。
- **INFERRED**：该边界符合 OWASP 对 Web Storage 的风险判断：不要把敏感信息、凭据或会话标识放进 localStorage；存储对象也不应被视为可信输入。证据：OWASP HTML5 Security Cheat Sheet 和 Session Management Cheat Sheet。
- **UNKNOWN**：真实第三方消费应用是否在发送前再次上传、保留或训练事项文本，当前无法由本地页面确认；需要按服务商和账户逐一核验。

## P0-3：导入数据不能破坏本地时间账本

- **VERIFIED**：正式 entries 必须有合法日期、开始时间、结束时间、标题、事项类型和唯一 ID；drafts 可保留空时间，便于继续编辑。重复 ID、无效日期/时间、非法完成记录和错误 trials 会被拒绝。
- **VERIFIED**：导入前把当前数据写入备份；新数据校验或保存失败时，原数据保持不变；最近备份可交换恢复。
- **INFERRED**：正向校验、失败回退和可恢复备份共同降低了损坏导入造成的不可逆数据丢失风险。OWASP Input Validation Cheat Sheet 要求在使用输入前验证其格式和约束。
- **UNKNOWN**：旧版本所有历史导出样本是否都符合“正式 entry 必须有时间”的新约束，仍需跑一批真实导出回放；当前只覆盖构造的合法旧数据与恶意/损坏样本。

## 页面与 UI 的可见表现

1. **今天页**：事项卡下方不再显示固定的“预计省 15–20 min”，而是显示“时间收益待实测 · 样本不足”；当个人历史满足门槛时显示“个人差值 X–Y min”。
2. **查看模型能力**：显示“任务级效果未实测”、任务对应的三步操作、可复制提示词、官方能力链接，以及“待实测 · 不承诺节省时间”的解释折叠区。
3. **完成事项**：完成表单要求填写执行、准备、核对、返工成本，并选择“待核验 / 已核验 / 需返工”。只有“已核验”才能产生可安排的时间选择。
4. **回顾页**：顶部依次展示“个人历史参考”和“已验收差值”；样本不足显示“待实测”，待验收项只在待验收列表出现。
5. **设置页**：显示本地存储说明、事项文本发送说明、会话密钥提示、consent 复选框，以及导入失败和备份恢复反馈。

## 尚未闭环的 P0 证据

- 用户实验：不同人群是否理解“待实测 / 个人差值 / 已验收”的区别。
- 模型对照：同一任务、同一输入、同一验收标准下，不同模型的质量、耗时和返工率。
- 真实账户可用性：地区、套餐、模型额度、文件大小、消费应用权限。
- 恢复演练：跨浏览器、清缓存、旧版本导出和多次备份交换。
- 真实隐私审计：网络层、第三方应用数据留存、组织账号合规要求。

这些项目不能由静态代码或本地单元测试替代，必须进入上线前的用户研究、模型评测和安全验收。
