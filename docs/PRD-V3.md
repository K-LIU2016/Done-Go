## 1. 版本定位与产品原则

### 1.1 保留的思想，不重新发明的能力

V2 的核心资产是责任、边界和授权之间的区分，不只是 18 个页面。V3 继续以一段由本人决定的时间为核心对象，不把日历填满、不以任务数量奖励用户，也不把 AI 对人的推测升级为事实。已有 PRD 与实现合同中的以下约束继续有效：

1. 未知不等于空闲；请求不等于已接受的责任；建议不等于本人意图。
2. 方案不等于授权；授权不等于执行；工具成功不等于外部结果已核验；外部结果不等于本人获得价值。
3. 草稿已审阅不等于已发送、送达或被接受；延期不等于完成，也不等于节省时间。
4. 保护时段允许没有用途。系统不得将恢复出的时间自动填入工作、推荐、打卡或商业机会。
5. 本人可以拒绝、修正、暂停、撤权、导出和退出；“维持原状”“没有可行方案”“什么也不安排”都是有效结果。
6. AI 只能在已允许的数据范围内提出候选项，不能接受责任、授予自己权限或代替另一方同意。管理员身份不等于阅读用户私人内容或代用户执行的同意。
7. 执行后保留能解释发生了什么的记录；不确定就显示不确定，不能靠重试按钮掩盖副作用。

来源：现有 `docs/PRD.md`、`docs/V2_IMPLEMENTATION_CONTRACT.md`、`docs/CONTEXT-REVIEW-SYNC-CONTRACT.md`。这些是继承约束，不记作 V3 新增创新。

### 1.2 市场判断与版本选择

官方材料显示，任务日历、多视图、自动排程、专注时间保护、AI 建议、预览与确认已经出现在 Todoist、TickTick、Sunsama、Motion、Reclaim、Akiflow 的不同产品中。特别是 Reclaim 2.0 的官方私测介绍已包含日历沙盘与 Review & apply changes；因此“AI + 日历 + 人工确认”不能单独构成 Tango Done&Go 的差异化。不能把私测或开发中功能当作普遍可用能力。[研究 S01–S15]

V3 的可检验差异化假设是：**更少的监督成本、更清楚的责任和未来负担、更严格的边界与不行动权**。这不是已被市场验证的护城河。首先证明用户在一个真实冲突中愿意继续使用它，再决定扩展协作与自动化。拒绝把供应商营销数据当作用户需求、因果证据或市场规模。[研究 H1–H5、S18–S20]

### 1.3 成功承诺与非目标

V3.0 对个人用户的承诺：真实空态可用；数据在支持的设备间延续；天/周/月反映同一份责任与安排；一个支持的外部动作可以从预览、授权到读回和恢复完整闭环；恢复出的时间不再被普通提示侵占。

V3.0 不建设完整项目管理、团队聊天、知识库、习惯养成、万能代理、自动议价或消息代发；不移动他人会议，不自动接受他人请求，不承诺系统级免打扰、全端原生集成或端到端加密。P1/P2 是后续候选范围，不随本 PRD 一并默认启动。

## 2. 用户、任务与核心闭环

### 2.1 首批用户与任务

主用户是假设中的个人知识工作者、独立协作者或小项目负责人：每周有多次来自他人的责任，有一定调整方法或时间的余地，个人时间经常被侵占。不预设职业、年龄、心理状态或家庭关系。首批用户选择必须通过访谈验证，而非从邮箱推断。

| 情境 | 本人真正要完成的任务 | Tango Done&Go 应提供的结果 | 不应承诺 |
|---|---|---|---|
| 晚间私人时间受到交付压力 | 看清可以减掉、改法或协商的部分 | 有代价说明的选择与可核验动作 | 每次都能找到无代价解法 |
| 临时收到一个请求 | 决定是否以及以什么条件承担 | 原话、未知项、本人接受的版本 | 收到即自动加入责任 |
| 中断后重新开始 | 恢复上次真实进度 | 检查点、待判断项和下一步 | 根据推测编造完成进度 |
| 准备一个材料草稿 | 少做重复整理，保持控制 | 来源明确、可编辑、未发送的草稿 | 生成即正确或已经交付 |
| 不想再被打扰 | 保持边界并知道尚未解决什么 | 低频必要提醒、可暂停和接管 | 屏蔽其他应用的所有通知 |

### 2.2 一次边界事件（Episode）的主路径

```text
本人选定要保留的时段
  → 汇合真实责任、来源覆盖与未知项
  → 判断是否冲突／信息不足
  → 至多 3 个有实质区别的方案 + 维持原状
  → 查看具体变化、披露、人工成本与未来负担
  → 对有实际后果的动作给出有限授权
  → 执行、逐项读回、处理部分成功或未知
  → 边界状态可解释，普通提示停止
  → 保护时段结束后可选反馈，不回答也成立
```

Episode 是一次需要本人选择的情境，不是一条新的待办。它连接现有对象，不复制责任。相同输入版本只建立一个活动 Episode；重新进入页面继续原事件。无冲突时只显示边界和来源覆盖，不强行生成三套方案。新责任或相关来源变更可以重新打开判断，但不自动覆盖先前决定。

### 2.3 具体演练，非用户真实数据

设计样例：2026-09-14，本人要保留当地 19:00–20:00；17:00–19:00 有 120 分钟可安排，其中固定事项 30 分钟、报告预估 60 分钟、行政事项预估 40 分钟，共需 130 分钟。

- 原状：显示 10 分钟缺口，但不能假定本人同意牺牲保护时间。
- 改方法：草稿辅助可能减少报告投入，必须标明估计范围、人工核对成本和前提；不能固定声称 60 分钟变成 40 分钟。
- 延期：把同一行政责任的 40 分钟安排移到本人选择的当地日期；若选“明天”则是 2026-09-15，不写成任意两天后。今日释放 40 分钟、未来增加 40 分钟，净节省保持未知。
- 协商：涉及他人约定的截止时间，只能准备建议；未取得对方同意前原责任仍有效。P0 不发送协商消息。
- 保护：如本人选择外部标记，可在受支持日历创建私人“不可用”块；这不证明其他应用已静音，也不证明他人不会安排会议。

样例只在显式演示模式出现。新注册用户不得看到这些内容被冒充为自己的实际日程。

### 2.4 减少监督负担的体验约束

主界面只回答“我想保护什么、什么正在影响它、现在需要我决定什么”。默认预览回答四件事：改什么、影响谁或传出什么、什么仍未知、怎样停止或恢复。版本号、回执、权限细节放在可展开检查区。保存私人草稿和修改私人标签不需要仪式化授权；外部写入、内容传出和不可恢复操作必须有匹配后果的明确确认。

### 3.3 首个外部连接器建议（待 D03 审批）

建议先实现 Google Calendar 的一个账号、本人拥有的主日历。读取经本人选择的日历范围；写入只允许 Tango Done&Go 自己创建的私人 busy 块，无参会人、无会议链接、无提醒、通用标题“不可用”。不修改既有非 Tango Done&Go 事件，也不移动共享会议。

这是一项待审的实施顺序建议：既有方向曾选择 Apple Calendar，不可默认为已被 Google 替换。如果首批用户的关键日历是 Apple，应选择 Apple，并先验证 EventKit/CalDAV、后台运行、权限和公网部署条件；不能为了兼容在 P0 同时开两条未经验证的写入链。Google 的 OAuth 审核/权限、提醒字段效果和实际用户覆盖也属于 R0 决策依据。[研究 S21–S23；差距 G07]

## 4. 信息架构与体验规范

### 4.2 视觉继承与交互规格

默认瓷白设计仍以附件及 V2 设计合同为基线，水墨为可切换的第二主题，不重新设计产品信息架构。共用语义 token、布局尺度、控件状态和图表语义；主题不得改变业务逻辑、权限或信息密度。品牌统一为 Tango Done&Go。

水墨基调：画布 `#F5F1E8`、纸面 `#FCFAF5`、炭墨 `#282A27`、次级暖灰 `#747168`、描边 `#DCD5C8`；朱砂 `#A44335` 仅小面积强调。以实测对比度为准，不因参数被建议过就允许不可读。中文展示标题采用现代宋/明体气质，英文展示标题采用克制衬线；正文与操作用无衬线，数字采用等宽数字。

8px 间距基线，桌面主要区域约 24–40px 内边距，卡片 12–18px、小控件 6–10px 圆角档位。水墨装饰仅在首页边缘、空态和静驻区域，密集日历/表单/图表退场。普通反馈约 160–240ms，抽屉约 240–360ms，减少动态效果时去除非必要位移与装饰动画。不得以色彩单独表示选中、失效、异常或未发送。

统一关键状态：加载、空态、部分数据、只读、离线草稿、冲突、权限不足、过期、执行中、核验中、部分成功、未知、已暂停、已删除。每个状态说明“已发生什么、未确认什么、现在能做什么”；错误不能只显示不可理解的代码。

按钮示例：“保存私人草稿”“允许本次创建日历块”“已提交，正在核验”“结果未确认，查看原日历”“明日增加约 40 分钟负担”。禁止使用“搞定”“已保护所有渠道”等超过证据的总括成功文案。

## 5. 领域对象与状态约束

### 5.1 权威对象与共有字段

所有业务对象具有稳定 `id`、服务端派生 `ownerId`、`revision`、`schemaVersion`、`createdAt/updatedAt/deletedAt` 与来源标记 `real/demo/imported`。客户端不能提交可信 owner，也不能通过切换账号继续应用旧响应。时间对象另存 IANA 时区和当地日期语义。

| 对象 | 关键字段与关联 | 约束 |
|---|---|---|
| Intent / ProtectedBlock | 本人表述、时间、可空用途、有效状态 | 推测不能写入确认字段；保护用途可 null |
| Episode | 关联意图/责任/来源版本、冲突摘要、选择、结果 | 不复制责任；同一输入版本去重 |
| RequestVersion | 原文、来源、提出者、范围、截止时间、未知项、本人回应 | 新条款新版本；接收不等于接受 |
| Commitment | 接受的请求版本、所有者、投入区间、截止类型、生命周期 | 安排与责任分离，完成需显式报告 |
| ScheduleAllocation / DeferralRecord | responsibilityId、时间片、前后日期、移动量、理由 | 同一责任的时间分配；延期成对记账 |
| SourceConnection | provider/account/calendar、能力、覆盖、freshness、撤权 | 已连账号不代表所有来源已覆盖 |
| Plan / ChangeSet | 输入版本、候选理由、动作 DAG、精确差异、披露、估计 | 预览与执行使用同一规范化不可变载荷 |
| Approval | actor/owner、hash、目标版本、许可动作、披露、期限、消费状态 | 一次消费；不扩权、不跨对象复用 |
| Operation / ActionReceipt | 幂等键、执行阶段、外部 ID、逐项结果、证据时间 | unknown 不覆盖；补偿是新操作 |
| Draft / MaterialGrant / Checkpoint | 小节正文、来源引用、处理许可、复核版本、下一步 | 审阅与发送独立；撤回不擦除历史 |
| AttentionItem / Delivery | 对象/到期/优先级、预算日、渠道、投递/展示/已看状态 | 创建不算打扰；跨端共享预算 |
| Agreement（P1） | 各方、共同条款版本、逐方回应、到期和执行引用 | 同版本同意才成立，不授予日历权 |

### 5.2 状态必须分维度保存

```text
请求：捕获 → 待澄清/待本人决定 → 接受 / 拒绝 / 保留想法
责任：已接受 → 可行动/待补充 → 进行中 → 本人报告结果 → 关闭/争议/未知
方案：候选 → 已选择 → 已预览 → 可批准 / 已失效
批准：未给出 → 有效 → 已消费 / 已撤销 / 已过期 / 已失效
操作：已登记 → 执行中 → 核验中 → 已核验 / 已确认无效果 / 部分成功 / 未知
草稿：准备中 → 待复核 → 部分复核 → 已复核（与发送状态独立）
保护：本地规则状态 × 外部覆盖状态 × 来源新鲜度 × 本人体验反馈
暂停：运行 → 已暂停 → 本人明确恢复；恢复必须重新验证，不能重放旧批准
```

责任取消、重新打开和修改范围都保留历史。只报告“本人认为已完成”，不能变成外部验收通过。延期修改安排和负担，不改变责任身份或伪造对方同意。部分执行保留每个动作结果：例如草稿已生成、日历块未知不能合并为“方案已完成”。

### 5.3 时间与容量的一致口径

所有时间重叠采用半开区间 `[start,end)`，19:00 结束与 19:00 开始相邻允许。保护、固定占用和缓冲先合并区间再计算，避免重叠重复扣减。

```text
W = 本人确认的可安排窗口，不是整个自然日
C = duration(W − union(保护区, 固定 busy, 必需缓冲))
D = [Σ可调整责任的投入下界, Σ可调整责任的投入上界]
G = [max(0, D.lower − C), max(0, D.upper − C)]
```

已经从 C 扣除的固定事项不能再计入 D。任务关联的日历时间片不能又作为独立责任重复统计；无法可靠关联时显示待核对，不能凭同名自动合并。未知投入不按 0 处理，显示“已知负担 + 尚未估计项”；未知来源不能显示“全天空闲”。

跨日切片之和等于原始区间；全天事件使用当地 date 而非假定 UTC 零点；重复事件由 seriesId + occurrenceId 标识，例外不重复展开。夏令时不存在或重复的当地时间必须提示并由本人确认；更换显示时区不改变已经确认的绝对时间。未完成安排过期后进入未安排/待处理，不自动标为完成或复制到每天。

今日释放、未来负担、实际耗时和净节省分开记录。没有真实对照依据时 `netTimeSaved = null`，不得用前后计划估计差直接宣称“帮你省了多少小时”。

## 6. 模块详细需求

本节 V3-01 至 V3-43 属 P0，V3-44 至 V3-46 属 P1，V3-47 至 V3-48 属 P2。每条需求对应第 9 节同序号 Axx 验收场景；阶段目标不是实施完成声明。

### M01 账号、注册与真实冷启动（P0）

**V3-01 验证码与会话。** 注册、登录、密码重置采用明确区分的用途；验证码绑定规范化邮箱、用途和一次挑战，不可跨用途复用。拟议有效期 10 分钟、重发间隔 60 秒、连续错误 5 次后终止该挑战；新码使旧码失效。邮箱/来源双维度防滥用，不以封禁共享 IP 为唯一策略。时间由服务端判定；成功后原子消费；重置密码撤销旧会话。面向未登录用户的响应不泄露邮箱是否存在。

**V3-02 真实邮件闭环。** 保留 Resend 作为既有发送路径；配置成功、服务商接受、邮箱收件、验证码消费、注册完成分别记录。生产响应和日志不返回验证码，不暴露发送密钥。发送失败可安全重试但不制造多次有效挑战；超时说明“发送结果未确认”，并限制重发。必须用授权测试邮箱证明收件、过期/错误码、注册/重置和随后登录，不能用 console devCode 替代。

**V3-03 真实空态和最小个人资料。** 新账号先选择时区、周起始日和一段可选保护时间；可跳过连接日历，明确只在本产品范围内有本地计划。演示通过显式入口进入隔离数据空间，醒目标记、退出不污染真实账号。邮箱用于认证，不自动推断职业、关系或性格。现有认证文档提及 mail2profile；本轮未重新调用不可用的 skill，不把该名称当作已验证的身份丰富能力。任何附加资料来自本人填写或另行知情同意。

### M02 服务端数据、离线与迁移（P0）

**V3-04 所有权与跨设备。** 业务数据由服务端统一保存，账号拥有自己的对象、设置、配额、导出和任务。跨设备使用同一 revision；退出立即清除当前内存视图和账户敏感缓存引用。迟到的旧账号响应必须丢弃。管理员也不能通过换 owner 参数访问内容。无权资源统一返回不可访问，不通过列表、计数、搜索或操作 ID 泄露。

**V3-05 离线与冲突。** 离线允许查看明确标记的缓存和保存私人草稿；禁止批准、外部执行和把缓存宣称为最新事实。草稿恢复联网后提交原命令 ID 与基准版本。冲突展示两边差异供本人选择，不以最后写入覆盖责任或批准。只对可合并的无副作用字段做确定性合并；过期授权与离线积压动作不自动执行。跨端草稿合并不会重发模型请求。

**V3-06 V2 数据迁移。** 首次升级发现旧 origin 数据时，先展示数量、日期、来源类型与将归属的账号，让本人导出备份并明确导入；不能因刚登录就自动认领公共浏览器数据。仅导入明确选择的真实/导入数据，fixture 独立。以源空间 ID + 对象 ID 去重、保留稳定关系和版本历史；中断可继续，不重建已消费批准。未确认操作迁移为只读待核对，不重新派发。导入完成核对总量/引用/抽样内容，原备份保留至本人确认删除。

### M03 天、周、月与安排编辑（P0）

**V3-07 同源多视图。** 天、周、月均使用同一选择器和区间算法，提供今天、前后期、指定日期和跨视图选中日期延续。周起始可配置，默认周一；月历支持按月份产生 4/5/6 行及邻月格。月格展示有限条目、准确剩余数和可展开清单；“无已知记录”不能写成“完全空闲”。日视图保留责任/边界双轨，周视图可按小屏转清晰的逐日列表。

**V3-08 真实 CRUD。** 可以新增、编辑、完成/取消/重新打开责任，以及创建/移动/缩放/移除自己的时间安排；这些是不同动作。键盘与表单覆盖所有拖拽能力。普通私人编辑有可见保存状态和有限撤销；外部相关编辑进入精确预览。拖动预览同步更新时间和容量，越界不静默吸附覆盖保护块。只读来源点击后解释限制并可打开原工具，不能伪装已编辑。

**V3-09 时间边界与重复事件。** 覆盖跨日、跨月/年、闰日、全天、多时区、夏令时和重复事件例外。P0 的本地重复安排至少支持每天、每周指定星期、结束日期或次数，并可编辑/跳过单次或整个系列；“从本次以后”若不支持须禁用并说明，不能静默修改整组。复杂外部重复系列 P0 只读。到期未完成的责任继续存在，安排过期不复制责任；处理逾期需要本人决定。

**V3-10 容量与汇总。** 按第 5.3 节计算，月/周汇总可追溯到每日对象。区间、单位、图例和“估计/实际/未知”必须可辨识。多个来源指向同一对象可靠去重；不确定关联由本人核对。筛选只改变视图不改变真实容量。工作时窗之外不自动当成待利用空间；小屏保留关键数值、标签和列表可达性。

### M04 请求、责任与未来负担（P0）

**V3-11 请求入口与接受。** 文本/分享内容首先成为请求或意图草稿，显示原文、来源、提出者、投入、截止、承诺对象及未知项。日期/人名有歧义就待澄清。接受由本人操作，可部分接受明确范围并形成新版本；拒绝、保留想法、归档不会新增责任或发送回复。重复录入提示可能重复，不因相似文字自动合并。

**V3-12 责任生命周期。** 记录接受版本、预计投入区间、固定/弹性截止、状态与实际结果。本人完成报告、对方确认和外部工具状态分字段；取消/重新打开有原因和历史，不擦除证据。更改已对外约定的范围或截止产生“待协商建议”，不能覆盖旧承诺。未被连接器验证的完成只称“本人已标记完成”。

**V3-13 延期与负担成对记账。** 同一责任保留 ID，记录原日期、目标当地日期、移动投入区间、目标来源覆盖和未决依赖。目标未知时允许保存未批准的草案，不保证可行；批准前本人确认已知范围与未知。移动安排不改变外部截止条款。今日释放和未来增加成对出现，历史回顾不把重复延期累加为节省。

### M05 任意输入的方案引擎（P0）

**V3-14 通用而可解释。** 从真实责任、本人保护区、已确认窗口、来源覆盖、截止与许可生成结构化候选，不依赖首/末任务或固定样例。确定性约束求解负责可行性；LLM 可建议改变方法、拆分投入或准备草稿，但候选要过相同校验。至多三个有实际差异的选项，少于三个就不补凑。显示每项为什么有帮助，以及哪些前提尚待确认。

**V3-15 估计、成本与披露。** 方案列出变化前后投入区间、人工复核成本、可能的模型成本、未来负担、受影响者、传出的材料与未连接能力。AI 估计有来源/置信说明且可改，不把输出字数折算为真实节省。未知价格显示未知，不能写“免费”；服务商自报 token 与本地估算区分。

**V3-16 不可行与拒绝。** 当硬约束冲突、信息不足或方案净负担更高时，分别说明原因。始终提供维持原状/稍后决定/本人修改边界，不能为求解成功自动放松保护、增加夜间工作或代替协商。被拒绝方案不在同一输入版本重复出现；只有相关事实改变才可说明原因重新建议。

### M06 预览、授权与暂停（P0）

**V3-17 单一变更载荷。** ChangeSet 用规范化数据保存动作、目标、精确前后值、披露、依赖、来源版本与排除项，生成稳定 hash。界面和执行器都从此对象读取；自然语言摘要不能暗藏额外载荷。动作可以逐项选择，但必须先检查依赖；不能批准写入却默认包含未准许的材料读取。普通保存无需引入外部动作授权。

**V3-18 有限一次授权。** 服务端将批准绑定当前 actor、owner、changeSetHash、允许的动作、资源与相关版本、provider/account、数据披露、授权到期时间。拟议预览授权有效 15 分钟，真正执行前仍检查目标新鲜度；过期返回预览，不沿用旧批准。相同批准只能消费一次，跨账号、修改载荷、重排依赖或更换模型提供方均不能复用。未选择动作明确排除。

**V3-19 精准失效与暂停。** 相关责任/目标/许可/披露/来源覆盖改变使对应批准失效，无关同步不能使全部草稿失效。总暂停阻止新外部派发及自动处理；在途尝试取消，已派发结果继续核验并明确不可保证撤回。暂停不会阻止本人查看或编辑私人草稿。恢复要本人明确点击并重新校验，旧批准不自动消费、旧未知动作不盲重试。

### M07 持久执行、读回与恢复（P0）

**V3-20 原子登记和幂等。** 服务器在同一事务中校验、消费批准并建立 Operation + outbox；工作进程按 operation/action 稳定 ID 派发。崩溃重启后继续原操作，不创建新的用户意图。客户端双击/多设备重试只有一个逻辑操作。幂等不是承诺网络 exactly-once；需要外部 ID、查重和未知恢复共同限制副作用。

**V3-21 逐项独立核验。** 每个写入先记录 provider receipt，再读取相同外部对象并比较受控字段和版本。仅有 2xx 不能标记已核验。部分动作成功时显示已成功、未执行、失败和未知的分别结果；依赖失败阻止后续，互不依赖动作是否继续由预览明确。审计保留目标 ID、时间和最小必要摘要，不在普通日志保存材料正文。

**V3-22 不确定与补偿。** 派发后超时/断线/进程退出进入 unknown，使用原外部 ID 对账；未确认前禁止生成新 ID 重做。provider 无法安全查明则提供原工具核对和人工接管。补偿删除/恢复也是新动作，需要匹配权限与当前版本，不能删除历史回执。手工外部修改优先呈现冲突，不自动“修复”用户的更改。

### M08 首个日历连接器（P0，待 D03）

**V3-23 增量权限与准确承诺。** 首选方案是 Google Calendar，连接时显示账号、日历、可读内容与授权范围。R0 验证 `calendar.calendarlist.readonly` + `calendar.events.readonly` 是否满足读取，只有本人首次批准写入时才申请必要写权限，候选为 `calendar.events.owned`。不默认申请包含共享/永久删除的全 calendar 权限。应用内选择主日历不是 OAuth 级最小权限，界面必须告知 owned scope 可能比单选日历更广；若权限不可接受就保留只读，而不是悄悄扩权。[研究 S21–S22]

**V3-24 覆盖与新鲜度。** 每个来源保存时间窗、完整性、最后成功同步、错误和撤权状态。拟议初始读取过去 30 天至未来 90 天，正常变化 60 秒内可见、超过 5 分钟标为可能过期，实际以配额与测量校准；范围外明确未知。同步令牌失效执行重建，不把空响应当成全部删除。缓存和推送通知仅提示可能变化，关键批准前重新读取有关目标，webhook 重复与乱序去重。

**V3-25 有限写入与可撤销覆盖。** 仅创建/更新/删除 Tango Done&Go 创建且属于当前账号的私人 busy 块：选定 owned 主日历，`summary=不可用`，`transparency=opaque`，`visibility=private`，`eventType=default`，无 attendees、conferenceData，并明确写入 `reminders: {useDefault: false, overrides: []}`，而不是依赖省略字段来表达“无提醒”；所有写入参数列入预览。稳定自定义 event ID 用于重试对账；读回起止/时区/忙闲/隐私/提醒设置等受控字段，提醒设置不能只用 `updated` 字段变化推断。外部来源不会阻止所有会议邀请，因此状态称“已写入所选日历”，不称“全面保护成功”。用户手工改块产生冲突；断连只撤销未来访问，不自动删块。退出时可另行授权清理 Tango Done&Go 块，已断连则给出原工具清单。[研究 S21、S23]

### M09 草稿、材料与工作现场（P0）

**V3-26 真实草稿生成。** P0 支持本人输入的文本/Markdown和明确允许读取的材料；不隐式爬取链接或上传所有私人上下文。生成在有界任务中进行，可取消，失败保留原文与手工编辑；不拿固定模板冒充模型成功。草稿始终未发送，无后台代发路径。未配置 LLM 时主计划与手工编辑仍可用。

**V3-27 来源与模型披露。** 每条材料保存允许用途、处理方、内容范围、期限与撤回。每小节列出来源引用、来源版本、推断与待核对点；引用缺失显示未知，不编造。把材料送到模型本身也是披露，连接模型成功不等于所有用户同意。更换提供方/模型数据政策/范围后重新请求受影响授权；引用材料内的指令只作为内容，不能改变工具权限。

**V3-28 逐节复核与连续恢复。** 小节编辑或相关来源变化只使相关复核失效；已撤回检查点不能被重新核对偷偷激活。检查点持久保存草稿版本、本人确认内容、未决项和下一步；跨设备打开同一对象。提供选中内容的 JSON/Markdown 导出，含来源摘要与未发送状态，不夹带未授权材料或其他草稿。导出不是发送给协作者，历史导出无法被系统承诺召回。

### M10 后台 LLM、隐私与成本（P0）

**V3-29 粘贴解析与启用。** 接受纯文本/Markdown的 Base URL、Messages/Models URL、API Key、Model；兼容空格、列表和链接显示文本。先展示解析结果，密钥遮罩，冲突 URL 或多模型必须选择，未知字段提示不能静默误用。流程为“解析 → 检查配置 → 连通/鉴权 → 模型列表或直接模型检查 → 小型推理 → 明确启用”。区分端口不可达、鉴权失败、协议不匹配、模型不可用、超时/限流；测试不会自动替换在线配置。

**V3-30 服务端网络边界。** 管理端认证及角色校验后才可测试。URL 禁止不支持协议、URL 凭据、云元数据、任意私网/本机探测和不受控重定向，防 DNS 解析后换址；本地部署允许操作员明确配置的精确 loopback host + port 例外，不把整个 127/8 或局域网开放给管理员输入。远程用户访问 127.0.0.1 指向服务器所在机器，界面明确这一点。公网运行时不允许用户借端点测试访问主机其他服务。

**V3-31 配置版本、密钥与个人同意。** 密钥仅服务端加密存储、权限受限、GET 只返回掩码；加密密钥与数据库/备份分开管理。日志、浏览器、导出、仓库不得包含凭据。管理员管理连接和健康，不提供查看私人提示词的默认功能；服务主机管理员技术上仍可能访问数据，需诚实告知，不能据 UI 权限声称端到端加密。配置有版本与回退；回退不能绕过个人的提供方许可。

**V3-32 配额和失败降级。** 拟议每人每天 20 次生成、每人 1 个并发，按实际调用而非 UI 点击计数；服务器统一执行，管理员可设置但有变更记录。展示 token、估算费用或未知以及重置时间。超限保留草稿、手工编辑与离线计划；不得无提示切换供应商。取消后迟到结果不覆盖新草稿；费用已发生和结果未应用分别表示。

### M11 注意力、静驻与反馈（P0）

**V3-33 持久到期队列与共同预算。** 到期由服务端持久任务驱动，不依赖页面开着。拟议主动提示预算每日 2 次，可设 0；按用户时区结算，跨设备同一事务抢占。创建队列项不耗预算，准备向用户暴露主动提示时原子预留，失败可安全释放；被动打开队列不重复计数。聚合同对象相同原因，延期再次到期不是重复创建责任。

**V3-34 投递语义与渠道。** P0 默认应用内队列；可选邮件提醒须本人 opt-in。分别记录已排队、provider 接受、设备展示、本人已看，无法证明展示就不填 displayed。浏览器关闭不伪称浏览器推送已到；邮件也不能从已接受推导已读。普通通知不含私人正文，链接进入本人登录态。重要执行异常持续显示在队列，不以高频外呼补偿状态设计。

**V3-35 保护时段的安静。** 在有效保护区内不投递普通建议、回顾、反馈或“利用空闲”的提醒；主动提示预算 0 同样禁止。真实账号安全/不可逆在途风险走独立、事先明确的必要通知策略，不能把一般任务升级为紧急来绕过预算。结束后合并且限额，不补发积压洪峰。本人选择保持静驻后不再询问用途。

**V3-36 可选回顾与价值判断。** 保护时段后低频问“这个结果是否符合你的选择/监督是否费力”，允许跳过、关闭和更正。未答是 unknown，不是满意/不满意或 0 分。回顾区分计划、实际、技术结果、未来负担与本人体验；不把延期或静默当成节省时间与用户价值。没有持续记录实际耗时就不展示精确效率成绩。

### M12 安全、退出与本地运维（P0）

**V3-37 后端强制边界。** 每个读写和队列动作检查会话、owner、角色、目标能力、来源许可、批准版本、暂停与幂等键。基于 Origin/CSRF 的请求防护、输入长度/类型/路径限制和登录限流由服务端执行；不能依赖隐藏按钮。导出、异步完成、后台队列和错误信息一起纳入跨账号测试。日志只保留最小诊断元数据；非必要遥测默认关闭。

**V3-38 导出、删除与断连。** 导出前验证本人身份，给出对象范围和未决操作清单。删除前区分账号/云端本地数据/浏览器缓存/备份/外部日历块；可先导出，删除期间停止新操作，已派发未知效果单独保留最小核对凭据。旧会话失效、在线数据拟议 24 小时内删除，离线设备下次认证时清理。第三方和已导出的数据不保证撤回；外部清理要另行授权。

**V3-39 保留与恢复后不复活。** 拟议个人业务内容保留至本人删除；普通日志不记录原始模型提示词，技术日志 30 天、最小审计元数据 90 天、加密备份滚动 7 天。不同数据分类、删除时点和备份到期向本人说明。删除 tombstone 随恢复流程应用，不能从旧备份重新激活账号、责任、批准或队列。保留期限与管辖义务待 D06 审批及必要的专业确认，本文不作法律合规结论。

**V3-40 本地服务运营。** 保留本人选择的本地主机 + Cloudflare tunnel 模式；应用、worker、隧道须托管启动与异常重启，监听仅限所需地址。新容器文件和 launchd 文档需要分别核验，不代表已满足运维门槛。健康区分活跃、就绪、数据可写、worker 积压、来源异常和邮件接受；不返回密钥。每天加密备份，拟议 RPO ≤24h、RTO ≤4h，以恢复演练证明；升级前备份、明确迁移/回滚兼容性。主机睡眠/断网时产品不可用，不对本地笔记本承诺 24×7 SLA。

### M13 体验、可访问性与性能（P0）

**V3-41 可访问性。** 所有主流程可键盘完成、焦点可见、抽屉/对话框有焦点管理、控件有标签与状态朗读，200% 缩放不隐藏操作，颜色以外有文字/图标状态。触控主操作拟议至少 44px，拖拽有表单替代；减少动态效果模式可完整使用。屏幕阅读顺序与视觉语义一致，忙碌状态不夺焦。

**V3-42 双主题与响应式。** 默认瓷白和水墨在关键状态共用组件与 tokens；拟议验收宽度桌面 1280/1440/1920、移动 320/390/430。不得出现页级横溢出、主要行动被遮挡、极低对比或图表装饰改变数值。浏览器操作、截图和委派 QA 只能使用 Codex 内置浏览器或 Ego Lite。附件严格 1:1 的旧验收缺口独立保留；新增体验设计需本人审阅，不用新主题掩盖旧缺口。

**V3-43 性能与资源预算。** 在记录 CPU/内存/浏览器/网络的固定基准机上，拟议 10,000 条业务元数据/5,000 个展开日历实例：常规无模型 API p95 <500ms，输入反馈 <100ms，缓存视图切换 <200ms，初次可交互 <3s。模型调用另报首响应/完成时间与超时，不混入 API 平均值掩盖等待。大列表分页/窗口化、重复事件有范围上限；网络失败保持草稿。指标需测量后决定，不能从 build 通过推导。

### M14 双人请求与同版本协商（P1，后续审批）

**V3-44 同版本同意。** 请求发起、收到、拒绝、反提案、撤回、到期和接受均有明确状态；只有所需双方同意相同有效条款版本才形成 Agreement。反提案不算接受；收件者能拒绝且不解释私人原因。一个人的点击不能把另一个人加入责任。

**V3-45 最小共享与身份绑定。** 共享内容限共同条款、必要时间和明确材料，不分享私人日历正文、保护用途、AI 推测或拒绝历史。邀请有期限、绑定预期身份并经登录验证；公开 bearer 链接不能直接读取私人内容。转发邀请不使第三人获得原人的权限；撤回停止未来访问，不保证召回已读内容。

**V3-46 约定与执行分离。** Agreement 是条款同意，不是双方日历操作授权。每人另给自己资源上的动作批准。旧约定在双方批准新约定或有效取消前保留，不被反提案覆盖；不同步、单边撤权、重复响应、部分执行均可解释和恢复。管理员不能代表任一方同意。

### M15 有限持续授权（P2，后续审批）

**V3-47 本人定义的有界规则。** 只有已验证的重复动作才进入持续授权候选。规则写明动作/资源/接收者/数据范围/时间窗/次数或成本预算/到期/撤销，并提供允许与拒绝的具体例子供本人检查。不从“习惯”“偏好”推断授权，不把一次同意升级为永久同意。默认关闭，不允许转授权。

**V3-48 独立执行器与撤销。** 每次动作由独立确定性门禁检查当前规则、预算、目标版本、保护区和暂停，不由 LLM 自评合规。撤销立即阻止未派发动作，已派发保留核验/接管；模型不能重新授权。跨人、外发材料、共享会议等新动作类别必须单独设计并经过真实验收，不能通过泛化工具接口顺带开放。

## 7. 架构演进与非功能要求

### 7.1 保留模块化单体，迁移权威写入

建议继续 React/TypeScript/Vite 前端 + Node 服务端 + SQLite 的单机模块化单体。复用现有领域命令、选择器、状态合同与 tokens；领域纯逻辑逐步迁移到可被服务端使用的包。不要为本版本引入微服务、向量数据库、事件总线集群或整站重写。SQLite 仅适用于当前单主机容量目标；多副本/托管扩展必须重新评估，不能在容器多实例间共享不可靠的本地文件。

```text
桌面 / 移动 Web
  ├─ 显示与交互：同一 domain view model、主题、日期选择器
  └─ 账户隔离缓存 / 私人离线草稿
          ↓ 会话 + 命令 ID + 预期 revision
Node API（唯一权威业务入口）
  ├─ Auth / Owner / Origin / Capability / Approval / Pause 门禁
  ├─ Domain commands + Query selectors + Schema migration
  ├─ SQLite：业务对象、版本、批准、Operation、Outbox、审计、删除标记
  └─ Durable worker：领取 → 再校验 → 派发 → 独立核验 → 记录结果
          ├─ Calendar adapter（单一受支持 provider）
          ├─ LLM adapter（最小上下文、个人许可、配额）
          └─ Mail adapter（认证与 opt-in 提醒分目的）
主机运营：进程托管、Cloudflare tunnel、备份、恢复与就绪检查
```

### 7.2 逻辑契约，不在 PRD 阶段锁死实现细节

| 契约 | 输入 | 输出与关键规则 |
|---|---|---|
| 查询业务视图 | 当前会话、日期范围、分页、displayTimezone | owner 内数据、来源覆盖、view revision；不接受任意 owner |
| 私人编辑命令 | commandId、type、targetId、expectedRevision、payload | 新版本或结构化冲突；重复 ID 同载荷返回原结果，异载荷拒绝 |
| 方案候选 | intent/commitment/source 版本集合、本人限制 | 可行/不可行/信息不足、候选及估计来源；无副作用 |
| 授权 | changeSetId/hash、选中动作、expiry、当前会话 | 精确 grant；不隐式执行未预览动作 |
| 执行 | approvalId、commandId | operationId 和状态查询入口；事务内消费与登记 |
| 恢复核验 | 原 operationId/actionId | 当前 receipt/unknown 原因；不能构造新副作用命令 |
| 撤销/暂停 | 目标 ID/版本、本人意图 | 停止未来派发；返回仍在途动作，不能假称已撤回 |
| 迁移/导出/删除 | 本人重新验证、显式范围、schema | 对象清单、校验和、操作状态与剩余外部边界 |

典型业务错误类别：AUTH_REQUIRED、FORBIDDEN、REVISION_CONFLICT、APPROVAL_EXPIRED、APPROVAL_INVALIDATED、PAUSED、SOURCE_STALE、PROVIDER_UNAVAILABLE、OPERATION_UNKNOWN、QUOTA_EXCEEDED。前端显示具体影响和可行动建议，诊断代码置于详情，不把所有错误归为“请重试”。

对外请求不与数据库事务一起长时间锁住：先事务登记，再由 worker 执行，最后独立记录结果。领取任务使用租约/原子状态更新与可恢复心跳；租约到期不直接证明外部动作未发生。OAuth token 刷新和撤权同样按账号串行控制，失败不冒用另一个账号。

### 7.3 安全与隐私威胁面

必须覆盖：跨 owner 的 ID 枚举、旧会话回调、导出与日志泄漏、CSRF、配置 SSRF、OAuth 回调 state/账号绑定、重复批准、任务重复派发、prompt injection、原材料越权、第三方数据保留、备份恢复复活已删除内容。产品门禁先于模型；来自网页/邮件/材料的自然语言不会成为系统指令。

本地托管模式的可信边界包括主机操作者和服务端进程。用户隐私说明须明确谁运维服务器、哪些内容会发送到哪个模型/邮件/日历提供方、如何关闭与删除。不得因只在浏览器隐藏后台接口，就承诺服务器看不到内容。安全设计验收不是正式合规或渗透认证结论。

### 7.4 迁移与发布策略

实现阶段先对原数据做可恢复备份，建立旧读模型与新服务器写入的迁移适配层，避免长期双主写。每个账号迁移要有 import manifest、对象计数、引用检查和本人确认。迁移回滚只能回到兼容 schema；一旦发生真实外部动作，不能靠回滚数据库假装外部世界回到过去，必须先对账。

功能开关按能力而非页面配置：serverBusinessData、calendarRead、calendarPrivateBlocks、llmDrafts、optionalEmail、pairAgreements、standingGrants。关闭功能保留可读历史与撤权入口。单独开启开关不构成产品批准或真实 provider 验收。

## 8. 指标、验证与发布门槛

### 8.1 检验价值，不奖励占满日历

主学习问题：一次真实边界事件是否得到本人认可的处理，同时减少而非增加监督负担？技术核验、个人价值、监督成本和未来负担分别报告，不合成掩盖失败的“效率分”。

拟议首轮 8–12 名自愿参与者、2–3 周形成性试用，不用于推算市场规模、统计显著性或疗效。记录参与者来源、退出者和缺失反馈，允许随时停止。访谈/试用尚未实施。

| 指标 | 定义与分母 | 防误读 |
|---|---|---|
| 真实边界事件量 N | 在真实来源/本人确认责任下发生且本人进入决策的不同 Episode | 演示、自动建议、刷新不计新事件 |
| 反馈覆盖率 | R/N；R 为收到本人结果反馈的 Episode | 未回应保持未知 |
| 本人认可率 | A/R；A 为明确认可处理结果的反馈 | 同时报告 A/N 下界，不能把 A/R 说成全体成功率 |
| 技术核验率 | 达到对应受控字段核验的外部动作/已派发外部动作 | 报告 partial、unknown 和恢复时长 |
| 监督成本 | 本人用于检查/修正/授权的主动时间与纠错次数 | 后台等待另列；没有测量就不猜分钟数 |
| 未来负担 | 延期投入区间、重复延期次数、逾期责任 | 不计作节省；不鼓励越移越远 |
| 边界违例 | 未授权动作、保护时段普通提示、自动回填和跨 owner 泄漏 | 任一严重事件停止扩大试用 |
| 来源理解 | 用户能否说明已覆盖与未知的范围 | 日历块核验不等于全面免打扰 |

### 8.2 研究任务与决策阈值

先做最近一次真实冲突的情境访谈，观察用户目前如何拒绝、延期、检查日历和恢复工作；再用低保真主流程测试，最后才进入真实试用。不要问“你喜欢 AI 时间主权吗”代替行为证据。重点反证：用户没有方法/时间决定权；确认流程比自己改日历还费力；真实来源缺口让方案无用；用户只要一个更好的任务列表。

拟议形成性理解门槛：8 次独立走查中至少 6 人能无主持人解释地完成主路径，并正确区分草稿/发送、授权/执行、已核验/未知。该小样本门槛只用于是否继续修订设计，不是商业成功率。若多数参与者认为监督成本不值得，先缩短主流程，不扩大自动化和团队范围。愿付费、长期留存和获客渠道均为 UNKNOWN，P1 投入应补充相关研究。

### 8.3 分层发布门禁

| Gate | 需要的证据 | 不可以替代它的证据 |
|---|---|---|
| G0 方向和体验审批 | D01–D06 决策、主路径/异常原型审阅、首个 provider 可行性 | 本 PRD 写完、模型推荐 |
| G1 静态与合同 | 所有者/状态/时间/授权合同、相关测试、类型/lint/build、精确版本 | 文件存在或历史测试总数 |
| G2 隔离运行 | 数据库/队列重启、并发、异常注入、迁移和备份恢复 | 单元测试全绿 |
| G3 真实界面 | 允许浏览器下主链、异常、双主题、移动、键盘、跨设备状态 | 18 页可渲染或有截图 |
| G4 真实提供方 | 邮箱实际收件注册；授权账号日历创建/读回/冲突/撤权/未知恢复 | HTTP 200、发送步骤、mock connector |
| G5 形成性价值 | 用户理解、监督成本、认可/拒绝/缺失反馈原始记录 | 自动化成功数、营销研究 |
| G6 固定本地发布 | 冻结 SHA/build/环境、恢复演练、运营说明、回滚与已知限制 | 容器文件、launchd 文档或健康页单次通过 |

每条验收记录绑定：需求 ID、环境、时间、完整 commit/build、数据模式、使用账号类型、执行步骤、预期、实际、证据路径、VERIFIED/UNKNOWN、残余边界。没有相应账号/权限则标 blocked/UNKNOWN，不伪造 provider 或用户结果。

以下任一项阻止扩大试用：未授权副作用、跨用户内容泄漏、重复不可控外部动作、责任不可恢复丢失、暂停失效、保护时段普通提示绕过预算。一般视觉细节可按影响分级，但关键信息或确认动作不可见同样是阻断项。
