## 1. 产品哲学

**一句话：AI 负责完成必须做的事，人负责成为想成为的人。**

未来会有大量 AI 帮人省时间，但几乎所有产品都默认省下来的时间会继续用来干活。留白只回答一个问题：**被归还的人生时间，应该流向哪里？** 它不是时间管理工具，而是在 AI 时代衡量、归还、并由本人重新分配人生时间的一层。

### 五条原则（来自设计宪法）

1. **时间不是资源，而是生命。** 不展示任务完成数、效率排名、连续打卡，只展示时间流向。
2. **AI 负责压缩，不负责占用。** 省下的时间默认变成留白，不被再次塞满；往留白里安排事情需要本人明确同意。
3. **不鼓励更多，鼓励更重要。** 不问“今天完成了多少”，问“今天最重要的是什么”。
4. **自由比效率更重要。** 核心指标是自由指数，而不是生产力分数。
5. **人的成长来自四种时间。** 恢复、创造、连接、探索（参考自我决定理论、Human Flourishing、Homo Ludens）。

### 四条诚实约束（来自仓库理论，本次写进主线）

1. **估算不等于归还。** AI 压缩给出区间；只有本人实际试过、记下前后用时，节省才算数。
2. **预留不等于留住。** 留白结束后由本人确认：完整留住、留住一部分、被占用、记不清。只有确认留住的进入账户。
3. **没记录不等于空闲。** 所有比例只基于本人记录的时间，未记录的空隙不被认定为空闲或浪费。
4. **请求不是责任，推迟不是节省。** 把事情挪到明天不算省时间；V2 的边界层（请求、责任、授权）继续负责必要时间那一侧。

另加一条：**留白不需要先挣来。** 任何时候都可以直接预留一段，不必先用 AI 省下时间。

## 2. 底层逻辑：Time Liberation Framework 的状态化

设计宪法的五段主线保留，但每一段都定义成有明确状态、由谁确认的对象：

```text
必要时间 ──► AI 压缩 ──► 归还 ──► 主动时间 ──► 意义时间
(本人记录)   (规则估算    (预留成     (本人决定用途，   (事后本人确认
             区间→本人    留白块)     或什么都不安排)   留住与用途)
             实测确认)
```

| 阶段 | 对象 | 状态 | 谁说了算 |
| --- | --- | --- | --- |
| 必要时间 | 时间记录（kind = 必要） | 已记录 | 本人 |
| AI 压缩 | 发现（估算区间）→ 尝试记录（前后用时） | 估算 / 已实测 | 估算来自规则；实测由本人记录，核对与修改时间计入“用 AI 后” |
| 归还 | 留白块 | 已预留 | 本人；默认不被再次塞满，重叠安排会先提醒 |
| 主动时间 | 留白块上的意向 | 可空 | 本人；意向不是任务，不提醒、不检查 |
| 意义时间 | 留白块的结果 | 完整留住 / 部分 / 被占用 / 记不清 + 用途（可空） | 本人事后确认；“空着本身”是合法用途 |

### 指标定义

- **今日可支配生命** = 每日清醒时长（默认 16 小时，可改）− 今天记录的必要时间。取代首页的待办数量。
- **自由指数**（0–100，只看过去 7 天）= 50% × 自主时间占比 + 50% × 创造与连接占自主时间的比例。自主时间 = 记录时间中除必要劳动以外的部分（含恢复、探索、留白）。只作描述：不和昨天比、不和别人比、没有目标值。
- **留白账户** = 本人确认留住的分钟累计，并按用途分布；同时如实列出预留、完整留住、部分、被占用、记不清的次数。
- **人生投资组合** = 7 / 30 / 90 天内各类时间占比；“理想比例”只在四种时间之间分配，由本人设定，可以不设定。

## 3. 产品形态

**全设备自适应（2026-10-11 第三轮）。** 同一套页面按屏幕宽度自动切换：
- 手机（窄于 720px）：单栏，底部六个标签，弹窗从底部滑出。
- iPad（720–1099px）：更宽的单栏，卡片两两并排，底部标签。
- 电脑与横屏 iPad（1100px 及以上）：左侧导航栏；首页和时间流分成两栏，左边固定是语音输入和待确认，右边是概览。面向首批用户（重度使用 AI 的高校教师、研究者、研究生）：他们忙，记录必须比打开日历更快。

**语音输入放在最上面。** 首页和时间流的第一块都是话筒加输入框：
- 一句话里可以说几件事（“下午两点到三点开组会，刚才回邮件花了 40 分钟，晚上八点留白一小时”），系统拆成几条，配好日期和起止时间，按关键词分到必要、创造、连接、探索、恢复、留白。
- 在 claude.ai 打开时，整理交给 Claude（第一次会征求同意）；其他地方或不同意时，用本地规则整理。
- 整理结果先进“待确认”，可以按时间或按类别排序，逐条改名、改类别、改时间；和已预留的留白重叠会标黄，需要明确点“仍然记下”。
- 浏览器不让直接打开麦克风时（例如在 claude.ai 页面里），提示用手机键盘自带的语音输入，效果一样。

**界面减法（2026-10-11 第四轮）。** 页面顶部只放 LOGO；“设置”只出现在页面底部右下角；宪章是设计思路，不在产品里展示（保留在本文档中）。所有说明文字压到最短，按钮和标题尽量两到四个字；诚实约束仍体现在行为上（估算与已省分开、留白事后确认），而不是靠解释文字。

六个主页面和设置页（下表的“宪章”一行已不在产品中显示）：

| 页面 | 回答的问题 | 刻意不做的事 |
| --- | --- | --- |
| 首页 | 今天还有多少可支配的生命？ | 不显示待办数量；不显示星级；自由指数不显示“较昨日 +5” |
| 时间流 | 时间实际去了哪里？ | 未记录的空隙标为“不认定为空闲”，不算损失 |
| AI 压缩 | 必要劳动里哪一部分能交给 AI？ | 不把估算写成已归还；“立即归还”改为“把它留白” |
| 留白账户 | 我真正留住了多少时间？去了哪里？ | 被占用不扣分，也不补算 |
| 人生投资 | 我的时间组合和我想要的差多少？ | 不提供标准答案；差距建议总附带“也可以不调整” |
| 留白建议 | 这段留白可以怎么用？ | 第一项永远是“什么都不安排”（默认）；不用星级排序；选了也不变成任务 |
| 宪章 | 留白相信什么？ | — |
| 设置 | 称呼、清醒时长、导出/导入/清空 | 数据不上传 |

### 相对设计宪法原稿的改动

| 原稿 | 现设计 | 原因 |
| --- | --- | --- |
| 今日归还 2h13m ★★★★☆ | 今日已确认节省 + 今天预留的留白，分开显示 | 估算与实测分离；星级是评分 |
| 自由指数 72，+5 较昨日 | 本周自由指数，附构成，不做日环比 | 日环比把自由变成绩效 |
| AI 发现“预计节省 35m” | 每天约可压缩 a–b 分钟（区间），注明是估算 | 单点数字会被读成事实 |
| 总计可归还 2h03m，按钮“立即归还” | 按钮“把它留白”，进入预留 | 归还的本质是保护一段时间，而不是一个数字 |
| 理想状态 35/25/25/15 | 本人设定；这组数字只作为可修改的起点 | 谁定理想比例必须是本人 |
| 留白建议 ★★★★★ 排序 | 默认“什么都不安排”；其余按本人理想比例的差距排序并写明原因 | 不替人打分 |
| 我的故事 | 合并进留白账户的“最近一次”与一句话备注 | 先让记录本身成为故事 |

### 第五轮：参考同类产品，砍到三屏（2026-10-11）

反馈：太复杂，看了不想看。参考了同类产品的做法后只保留三件事：

- **Opal / Apple 屏幕使用时间**：首页只给一个大数字（今天可支配）。
- **Structured**：时间线就是一条竖直的当天列表，前后翻天。
- **Sunsama / Daylio**：输入靠一句话加一次点按，留白确认只有“留住了 / 没有”两个按钮。
- **Reclaim / Motion**：不学它们的自动排程，只保留“预留一段时间”这一个动作。

结果：六个页面合并为 **今天 / 时间线 / 回顾** 三个。今天页只有可支配时间、语音输入和一张留白卡；回顾页只有留住的时间、自由指数、时间去向和可交给 AI 的事。理想比例、试验记录和建议页暂时下线，诚实约束仍在逻辑里（预留不等于留住，估算不计入）。

### 第六轮：把理念放回“今天”页（2026-10-11）

- **今天列表**：当天要做的事，可按时间或按优先（必要 → 创造 → 连接 → 探索 → 恢复）排序。
- **AI 压缩建议**：能用 AI 缩短的事，下面直接写“约多久、可省多少”，点“交给 AI”后条目缩短，省下的时间自动变成一段预留的留白。估算仍不计入“留住”，要事后确认。
- **留白头像**：07:00–23:30 每半小时一个卡通头像（不规则小方块），点几个就留出那几段；有安排的时段变灰。

- **时间树**（取代时间线列表）：中间一条微微弯曲的主干就是一天，左边长“必要”的叶子，右边长“自己的”叶子（恢复、创造、连接、探索），留白开成一朵花，事后确认留住了才会填满颜色。叶子大小随时长变化，交给 AI 的叶子带一个 ✦。主干和背景的颜色跟着一天的天色变：清晨粉橘，上午晴蓝和嫩绿，午后金黄，傍晚橙红，夜里紫蓝。今天已经过去的部分颜色饱满，还没到的部分是淡的，当前时刻白天显示太阳，晚上显示月亮。点叶子可以查看或删除。

- **冲突弹窗**：新记的事和留白撞时间（或点头像留白时撞上已有安排），会弹出“啊哦，时间撞了”，配一个手绘的担心小脸和一声“啊哦”提示音（设置里可关），让用户选“留白优先”或“这件事优先”，输的一方只让出重叠的那一段；也可以“先不记”。

## 4. 与现有 V2 / V3 工程的关系

- V2（React + Node，18 屏）是 **必要时间一侧的边界层**：请求不等于责任、方案不等于授权、执行要核验。它继续存在，代码未改动。
- 本次重新设计把 **Time Liberation 主线** 放到产品正面；`web/` 是它的第一个可用版本，单文件、无构建、无后端，可直接部署为静态页面。
- 后续合并方向：把 V2 的“保护时段”与本主线的“留白块”统一为同一对象；把 V2 的 LLM 设置用于 AI 压缩的真实估算（在本人授权的数据范围内）。

## 5. 上线标准与当前边界

已完成：

- 可直接打开的网页（见 PR 与项目线程中的链接），手机优先的单栏布局，浅色与深色主题。
- 语音或文字一句话记录，自动拆分、配时间、分类，确认后记下。
- 首次进入可选“从空白开始”或“看示例（研究者 Yajing 的三周）”；示例数据始终带横幅标注，可一键清空。
- 记录、预留留白、重叠提醒、事后确认、实测节省、理想比例、导出/导入/清空均可用。

尚未做（不应宣称已具备）：

- 压缩估算仍来自本地关键词规则，页面上已注明；只有语音整理会在 claude.ai 中调用 Claude。
- 不读取邮件、日历或任何外部账户；不跨设备同步，数据只在当前浏览器。
- 没有账号体系；没有提醒推送（这是有意的，留白不提醒）。
- 首批用户假设（重度使用 AI 的学术与研究人员）仍待访谈验证，见项目共享文件中的《留白-定位与竞品分析》（2026-10-10）。
