## 2. 终极目标：把 AI 素养带进每一件真实小事

探戈的核心成功是：原本不熟悉 AI 的人，在日常真实任务中逐渐理解不同模型能做什么、不能做什么，知道何时使用、怎样提出需求、如何验证结果，并把学到的方法迁移到下一件事，持续提高时间的使用质量与自主性。

时间可视化是入口；任务是练习载体；模型是可选择的工具；方法复用与独立判断是成长证据。帮助用户更快做完只是部分结果，不能代替核心成功。

原始目标持续保留：

1. 为高校学生、研究员、教师、公司职工等提供看得懂的时间去向。
2. 缩小日常生活、学术环境与 AI 发展之间的使用鸿沟，让用户看见合理使用 AI 的机会与真实代价。
3. 提供低门槛 AI 试炼场：结合具体事件解释模型差异、候选顺序、提示词和核验方式。
4. 帮助用户形成适应 AI 时代的习惯，从偶尔提问走向持续学习、主动选择和负责地使用 AI。

社会影响与千万级融资是长期愿景，不是功能上线即可兑现的结果。它们需要真实使用、质量、复用、付费与成本证据支持，禁止在产品或汇报中承诺必然实现。

### 2.1 成功与误判

| 观察 | 能说明什么 | 不能直接说明什么 |
|---|---|---|
| 用户打开模型卡 | 接触过推荐 | 理解模型差异 |
| 用户复制提示词或多次聊天 | 使用过工具 | 已形成 AI 素养 |
| 用户验收一次任务 | 这次结果被本人接受 | 换个任务也能独立完成 |
| 用户自述“会用了” | 主观信心 | 经观察验证的能力 |
| 用户能说明选型理由、主动检查结果 | 出现可观察的判断行为 | 对所有任务都适用 |
| 用户在新的相似任务中独立选择、调整方法并完成核验 | 对这类任务出现迁移证据 | 永久掌握或普遍社会效果 |
| 计划时间减实际时间为正 | 本次计划差值为正 | 差值全部由 AI 导致 |

## 3. 不偏离方向的设计原则

1. **从用户的事出发。** 不要求用户先学模型术语；先问“你要完成什么、结果怎样算好”。
2. **在行动中解释一件事。** 推荐时解释一个关键差异，核验时提醒一个关键风险；长知识放到展开层。
3. **帮助用户形成判断。** 可以一键开始，但用户应逐步知道为什么用、为什么换、什么时候不该用。
4. **质量先于速度。** 错误答案带来的返工、检查与准备必须进入成本，不能把速度包装成成功。
5. **允许不使用 AI。** 明确目标、自己做、请专业人士或暂时停止都可以是合理选择。
6. **把省下的时间还给用户。** 休息、关系、运动、学习或不安排均由用户决定，不把时间自动填满。
7. **默认简单，按需展开。** 首屏只有当前动作需要的内容，不把所有能力做成并排卡片。
8. **以复用减负。** 方法来自用户已有任务，允许先完成、以后再整理；记录负担本身也应被看见。
9. **诚实表达证据。** 区分模型/厂商说明、个人自述、任务记录、观察验证和未知。
10. **用户保有控制权。** 推荐不自动修改事项，不自动公开方法，不默认发送完整历史。

每新增功能都应回答：它帮助用户形成了什么判断？在什么真实任务触发？下次如何复用？代价和失败如何表达？如果答不清，先不占据主流程。

## 5. 两条相互连接的闭环

时间闭环保留：记录事项 → 制定计划 → 执行 → 本人验收 → 记录完整成本 → 决定时间用途 → 回顾。

学习闭环新增连接：理解任务 → 比较可用工具 → 使用并核验 → 保留方法 → 在相似任务中复用 → 调整方法 → 独立迁移。

两条闭环通过同一任务及其完成记录连接。方法复用失败也进入记录；不因为没有节省时间就抹去学习价值，也不因为“学到东西”就忽略严重质量问题。

### 5.1 一条具体体验示例

以下为设计示例，不是真实测量结果：

1. 用户记录“明天下午筛选 5 篇论文，整理研究问题与证据”。
2. 事项卡先帮助明确交付物和核验要求，再提供 1 个默认候选与按需展开的备选。没有可靠依据时直说尚无个人实测。
3. 用户使用模板，填入允许分享的公开资料；模型提取后，用户核对原文出处。
4. 完成后记录质量与总成本，选择“保留这次方法”，得到“论文初筛与原文核对”方法卡。
5. 下次出现相似任务，事项旁提示“你有一个相关方法”，说明匹配原因；用户可以不用。
6. 换成证据更复杂的资料时，用户修改检查清单或换模型。系统记录变化，不自动认定旧模型变差。
7. 回顾显示用户主动核验和修改方法的证据，而非仅显示问过 AI 几次。

## 6. 优先新增：我的 AI 工作手册

这是一组属于用户的可复用方法，不是另一个庞大的知识库或提示词商店。第一阶段从已有事项卡和回顾进入；确有导航需求后再考虑独立页面。

### 6.1 一张方法卡应该回答什么

| 信息 | 要求 |
|---|---|
| 名称与用途 | 用户能认出，例如“核对会议纪要与行动项” |
| 适用条件与不适用条件 | 说明交付物、资料要求和边界，不只匹配任务标题 |
| 开始所需材料 | 明确哪些由用户填入，哪些不能直接上传 |
| 模型候选与理由 | 保存当时依据与日期，允许替换；没有经验时标记未验证 |
| 提示词模板 | 使用变量槽位，默认不复制原始私人正文 |
| 操作步骤 | 少量可执行步骤，复杂解释按需展开 |
| 核验清单 | 如何判断正确、完整、可用、来源可靠 |
| 已知失败 | 常见误差、返工、暂停条件与替代做法 |
| 使用记录 | 引用具体任务结果与方法版本，不在模板里堆叠个人正文 |
| 控制 | 保存、修改、复制成新方法、归档、删除；有历史引用时解释影响 |

创建入口优先放在一次任务结束后：“这套做法，下次还用吗？”允许稍后整理与跳过。未验收、失败任务也可保存为待改进的方法，但不能标为“已验证有效”。

### 6.2 模板与隐私示例

~~~text
方法：资料初筛与原文核对
输入：[公开资料/获准材料]、[研究问题]、[输出结构]
要求：逐条区分原文事实、推断与缺失信息；给出可定位的出处。
核验：打开原文核对关键结论；找不到出处时标“无法核实”。
停止条件：材料不可分享、出处无法核对、关键结论有冲突。
~~~

用户修改方法产生新版本；历史任务保留当次版本引用或最小必要快照。修改模板不能改写过去的结果，删除方法不能删除任务本身或改变时间统计。

## 7. 优先新增：在下一件事中找回方法

只建立手册却找不回来，不能形成复用。触发点应在用户已有的事项上下文中。

- 先按任务类别、交付物、输入形式、核验要求与账户条件做简单、可解释的本地匹配；不要一开始引入向量数据库或外部画像服务。
- 同一类别不足以证明适用。输入规模、材料敏感性和交付标准冲突时，降级为弱关联或不推荐。
- 默认只展示最相关的一条，例如“可试用你上次的资料核对方法”，点击后展开；备选与全部方法按需查看。
- 展示具体原因：“同样是带出处的论文初筛”，而不是伪造“匹配度 98%”。
- 没有足够依据时允许空结果，提供“自己选择方法”。不能为了让页面有内容而强推。
- 用户可以忽略、替换、手动关联或取消关联；忽略不是能力失败。
- 应用前说明会填入哪些内容，只作用于当前目标；事项被修改或删除后，不应用过期建议。
- 拒绝匹配、未应用、应用后中止、执行完成应分开；只打开方法卡不记作成功复用。

方法可以省去重复操作，也应提示关键差异：“这次材料更长，先检查上下文限制”“这次包含未公开研究，先处理隐私”。

## 8. 个人模型经验：把选择依据讲清楚

用户需要的是“针对我这件事，有哪些合理选择”，不是永远不变的模型排行榜。

### 8.1 四种信息分别展示

1. **产品说明**：可追溯到官方资料的能力、输入限制和账户条件，带来源与日期。
2. **我的偏好**：用户主动选用的候选，不能等同于更好的效果。
3. **我的实际使用**：当次记录或服务直接证实的型号、版本与结果。
4. **我的可比经验**：经过质量、任务条件与样本筛选的历史观察，样本不足或缺失时保持未知。

聊天使用的配置模型、事项推荐候选与用户在外部实际使用的模型是三个不同概念。禁止由“推荐过”推断“调用过”，也不能由回答正文里的自我介绍证明供应商实际执行了某一型号。

### 8.2 可比与不可比

- 至少考虑任务类型、交付物、输入规模、验收要求、实际型号/版本、账户条件与记录来源。
- 质量与成本缺失、未核验、失败、示例、未知型号均不得悄悄筛成“优质样本”。保留各自状态与排除原因。
- 不可比记录可查看，但不硬合成一个“最强模型”。不要把不同用户的指标自动混在个人历史中。
- 少量样本直接呈现次数与原始观察；没有依据时不显示精确概率、置信分数或“为你节省 42%”。
- 反馈至少包括“质量达标吗、核对/返工多少、下次愿意用吗”；愿意用是偏好信号，不是客观正确性。
- 保留失败与负差值，不因成功率好看而隐藏未完成任务。只有可比样本足够时才考虑排序，并解释所用标准。
- 模型更新、访问失败或资料过期时保留历史版本事实，当前建议降低确定性，允许用户换工具。

个性化先来自用户主动选择的上下文、真实任务与方法，不从聊天内容自动推断健康、收入、政治倾向等敏感画像，也不建立隐藏人格评分。

## 9. AI 素养成长：从使用记录走向迁移证据

成长围绕具体行为：任务分解、提供上下文、表达约束、选择工具、核验结果、隐私判断与调整方法。沿用已有技能字段，按需补充，不新建不可解释的综合分数。

| 状态 | 页面含义 | 证据要求 |
|---|---|---|
| 试过 | 接触了某种做法 | 相关操作/任务记录；不称为掌握 |
| 在帮助下完成 | 借助引导完成并验收 | 帮助程度、结果、核验记录 |
| 自述可独立使用 | 用户报告自己的能力 | 明确标记自述，不升级为观察结果 |
| 在新任务中独立使用 | 没有逐步提示仍能选型、调整与核验 | 新任务引用、支持程度、验收与证据来源 |
| 在更多条件下迁移 | 在不同约束中解释并调整方法 | 多次带条件的证据；不标为永久精通 |

“独立”指不依赖探戈逐步提示来完成判断，仍可合理使用 AI；不能把 AI 素养定义为必须不用 AI。现有“关闭 AI 后复测”可保留为特定学习练习，不是所有任务的统一毕业标准。

可以逐步减少提示，但由用户选择：“继续带我做 / 我想自己试试”。用户卡住时可恢复引导；不扣分、不惩罚、不以连续签到压迫使用。

成长页从回顾中的小节开始：这次有哪些行为证据、下次可试哪个小变化。AI 总结只能提出解释与建议，不能自动发证书、判定熟练或修改用户自述。

## 10. 页面与交互改动

### 10.1 今天与事项卡

保留快速记录、时间去向和当前任务优先级。新增方法发现与简短能力解释，不重排全部导航。

- 每件事默认一个明确动作：“看看怎么做”或“使用相关方法”。
- 展开后才看适用条件、模型理由、提示词与核验清单；模型列表不是首屏主体。
- 模型比较重点回答“为什么适合这件事、关键限制是什么、还有什么选择”。
- 分类与优先级可以接受聊天上下文建议，但必须可见、可改、由用户应用，不暗中决定生活优先级。
- 外部模型故障不阻止记录、编辑、手动完成与本地回顾。

### 10.2 完成与验收

保留“完成”和“质量确认”的区别。主流程优先获得结果与必要时间；学习记录、详细成本与方法整理按需展开，不能把所有研究字段强制填完才能结束。

可选动作：“保留这次方法”“记下一处不靠谱”“下次自己试试”。不自动勾选分享/评测同意。失败方法可以保存为草稿并写明问题，不能计入已验证成功案例。

### 10.3 回顾

第一层只回答三件事：时间去了哪里、这次什么做法值得保留、下一次有何可选调整。详细模型经验、技能证据和统计口径折叠。

建议呈现的反思句式（需有数据支持）：

- “你这次主动核对了原文来源；下次可以沿用这份检查清单。”
- “这次总用时更长，主要增加在核对与返工；这套方法还需要调整。”
- “你已自述能完成，但还没有新任务的独立使用记录。”

数据不足时不生成空泛赞美、人格评价或虚假的“AI 改变生活”结论。用户可以纠正总结。回顾中保留休息与自主安排的价值，不将全部腾出时间导向更多工作。

### 10.4 和探戈聊聊

必须保留用户已确定的交互：

- 像短信一样简单，一个页面完成聊天与模型选择；避免重新增加大量 box 和说明文字。
- 用户点发送就发送，不恢复“发送前预览”弹窗。
- 回答来自真实配置模型；删除/过滤旧本地引导回复的规则不能被逆转。调用失败不能伪装成模型回答，也不偷偷替换其他模型。
- “由你决定，分享多少”保持折叠，用户可以查看、减少或关闭可选上下文；默认范围不得因省去预览而扩大。
- “我的目标与边界”不恢复；“链接与记录”保持折叠。
- 保留错误文案：“歇一会儿我们再继续吧，或者联系技术支持人员来为你开通新的探戈通道吧。”状态区须区分失败、等待与成功，不暴露服务内部错误。
- 页面底端小字技术支持入口，点击显示邮箱 yajing1906232977@163.com。

新增能力融入对话：解释候选差异、协助提炼模板、结合用户选择的记录做反思。整理方法属于建议，用户确认保存后才写入；应用事项建议继续校验目标与版本。

普通聊天发送、额外上下文分享、修改事项、保存方法与对外分享是不同动作。省去发送预览不意味着授权模型自行修改任务或上传完整历史。

### 10.5 时间线 / 时间之树

保留“时间如何分布”的主体。AI 成长可以作为可选视图或节点详情，连接相关任务与证据，不将时间之树改造成新闻信息流。

资讯/播客推荐须有原始标题、来源、链接、日期与获取状态；区分原文和模型摘要。无法检索时显示失败或带日期的已有内容，不能编造实时新闻、播客或来源。

用户可以把一条内容转成一次小实践，例如在自己的任务上试一个核验方法；先确认再创建事项。推荐可关闭，不自动生成每日任务、订阅或提醒，不用阅读量当学习成绩。

### 10.6 设置与数据

增加或整合方法导出、上下文范围、学习记录控制与数据清理入口，复用现有设置能力。说明本地存储按源隔离：localhost 与 127.0.0.1、不同端口、浏览器或账户的数据不会自动共享。

导出应区分个人完整备份、明确选择的脱敏指标与去除私人正文的分享模板；不要把完整备份当作匿名研究数据。

### 10.7 暂不扩展的页面

约定、语音等已有能力维持原业务边界。本轮不为了“丰富产品”新增组织后台、社交广场、课程系统、积分商城、强提醒和公开模型排行榜。

## 11. 后续可选：方法分享与共同改进

这是核心复用链验证后的选项，不能成为首阶段依赖。

- 先做用户主动导出/导入单个方法模板，再判断是否需要社区。
- 分享前剥离原始任务、聊天、身份、文件内容、使用时间线与凭据；隐私检查不能只靠正则识别名字。
- 展示实际分享内容与接收范围，由用户确认；本地创建方法不等于同意发布。
- 导入标记来源、版本与未验证状态，作为独立副本，不覆盖本地方法、不执行其中的指令。
- 外来模板与链接均是不可信内容；不得修改系统规则、自动访问外部地址或触发模型/工具动作。
- 收藏与点赞不能变成有效性证据；发布后删除本地内容无法收回他人已保存的副本。

## 12. 最小数据模型与兼容要求

以下是领域建议，不是当前已存在的字段名。执行模型必须先映射现有结构，能够复用的直接扩展，避免平行账本。

| 概念 | 最小职责 | 不承担的职责 |
|---|---|---|
| 任务与完成记录（已有） | 时间、质量、实际模型、学习自述与结果的权威来源 | 不复制成一套新的收益记录 |
| MethodRecipe（拟新增） | 稳定 ID、版本、用途、模板变量、步骤、核验、适用边界、状态 | 不存 API key，不默认嵌入原始私密内容 |
| MethodUse（拟新增或任务扩展） | 方法版本、任务引用、应用/中止/完成状态与用户调整 | 不把打开/复制等同于成功 |
| SkillEvidence（按需扩展） | 技能行为、任务引用、证据来源、支持程度与迁移关系 | 不制造不可解释的成长总分 |
| 个人模型观察（派生） | 从任务结果按可比条件生成视图，保留样本与缺失说明 | 不将推荐偏好写成实测效果 |

兼容要求：

1. 旧数据没有新字段时正常读取，显示“尚未记录”，不伪造默认成功、零成本或已掌握。
2. 迁移前保留可恢复原始数据或现有备份；迁移幂等，失败不覆盖有效记录。
3. 方法版本变化不改写旧结果；任务删除、方法归档、方法删除各自明确处理引用，不制造悬空成功记录。
4. 导入、导出、恢复包括必要的新实体与版本；遇到未知版本或冲突可解释地拒绝/隔离，不能静默丢失。
5. 同步冲突与多标签页行为沿用现有约束；新增保存动作也必须处理写入失败，不能先显示“已保存”。
6. 时间计算继续由 window.TangoTime 负责；该领域对象当前定义在 web/index.html 中，不另造时间计算器。
7. 拆分模块仅在帮助隔离新逻辑时进行。新增前端文件同时检查静态服务、构建交付与测试是否包含，不能只在开发目录有效。

## 13. 时间、质量和证据的统一口径

总实际成本 = 准备 + 执行 + 核对 + 返工。额外记录成本单列；如展示计入记录后的净差值，清楚标明口径，避免重复扣除。

- 计划减实际只能称为计划差值；未验收、失败和估算结果不能合并成已确认收益。
- 缺失不是 0；未知模型不是默认模型；没核验不是正确；没看到后续不是能力退步。
- 保留负差值、放弃和返工。只看成功完成者会高估产品价值。
- 自报用时、观察计时、真实服务执行信息和厂商宣传分别标记。
- 如研究 AI 的因果贡献，另做可比任务、相同验收、顺序控制和外部中断记录；不在普通回顾中伪造实验结论。
- 预留自己的时间与事后真正使用分开，禁止自动把预留当成生活改善。

### 13.1 面向复用的指标

先固定研究定义与分母，再计算结果；不预设一定达到的百分比。

| 指标 | 建议定义 | 必须同时呈现 |
|---|---|---|
| 核心激活 | 同一人首次完成记录 → 本人验收 → 查看回顾 | 纳入人数、失败、退出与版本 |
| 方法保存 | 用户明确保存的方法 | 草稿/已验收来源，不等同复用 |
| 发现与应用 | 有相关方法的真实机会中，看见、选择与应用的情况 | 匹配规则与版本、忽略与无匹配；不能自称覆盖所有机会 |
| 完成复用 | 在后续新的真实任务中应用方法并完成验收 | 适用机会、应用次数、中止/失败与质量 |
| 独立迁移 | 新任务中减少逐步帮助，仍能选择、调整和核验 | 证据来源、任务条件、未测试与自述单列 |
| 净成本 | 质量达标前提下的总成本及记录负担 | 缺失、负差值、任务可比性 |
| 时间自主 | 用户主动选择与实际使用时间的记录 | 未记录与仅预留，不推断生活满意度 |
| 留存与流失 | D7/D30 新真实任务验收，沿用既有 ±1 天窗口 | 合格 cohort、退出、失访、尚未到观察期 |

单浏览器记录不能自动产生跨用户留存、付费与社会普及率。没有用户同意的研究编号与纵向设计时，页面只能给个人观察。

## 14. 隐私与 AI 行为边界

- 任务、方法、聊天与成长信息默认本地保存，外发范围沿用当前有效同意；新增字段不自动加入上下文白名单。
- 保存方法不触发模型请求；本地匹配优先在本地完成。需要外部模型时明确用途、范围与用户动作。
- 用户选择不分享历史时，聊天仍可基于本次输入回答；不要以“个性化需要”强制开启全部记录。
- 现有同意不能被解释为跨用户遥测、自动评测上传、公开方法或训练授权。
- 清空聊天、删除方法、删除任务与导出文件各有独立范围。删除本地数据不代表撤回已发送到供应商的数据。
- 调试只使用必要的状态、脱敏错误编号和经同意的材料；不记录完整聊天与私人任务正文。
- 模型生成的方法、反思与网页内容都必须按不可信输入处理：转义渲染、限制链接协议、不执行脚本、不绕过授权。
- 未经用户主动选择，不打开外部模型网站、不启动付费请求、不替用户对外执行事项。

## 15. 分阶段实施顺序

本说明用 D0–D5 区分新一轮设计，不复用历史 P0/P1 的“已收口”标识。

| 阶段 | 工作范围 | 可审查交付 | 完成条件 |
|---|---|---|---|
| D0 基线校准 | 核对真实入口、已有字段、旧文档冲突与当前工作区 | 简短差异表、预计变更文件与已有测试映射 | 不重复建设，不恢复旧聊天，不影响用户改动 |
| D1 方法形成 | 从事项完成记录保存/编辑/归档方法，模板变量与版本 | 一条从任务到方法的可运行流程 | 隐私、保存失败、旧数据、历史引用可验证 |
| D2 方法复用 | 相似任务发现、解释原因、手动选择、应用与中止 | 今天 → 方法 → 新任务验收 → 回顾闭环 | 无匹配不强推，过期目标不应用，复用有真实结果 |
| D3 模型经验与成长 | 可比模型观察、证据来源、减少引导与迁移 | 用户能解释推荐依据，回顾能指出证据不足 | 不伪造排名、能力、样本或时间收益 |
| D4 反思与内容 | 轻量反思、时间之树任务关联、可选内容实践 | 有来源、可拒绝、可纠正的日常体验 | 不改变简洁聊天，不将资讯流当成长 |
| D5 可选分享 | 仅核心验证后考虑模板导入导出与分享 | 可审查内容、明确确认与不可信输入隔离 | 不泄露私密记录，不引入社区依赖 |

第一轮优先完成 D1 + D2。D3 的最低证据边界应在 D1 起就保留，但不要等完整成长系统建好才让用户使用方法。

每阶段采用“数据/边界 → 领域行为 → 界面 → 相关验证 → 结果报告”的小步交付。不要把整个产品一次性替换，也不要为了完成所有阶段而编造使用证据。

## 16. 验收场景：必须包含成功与失败

| 编号 | 场景 | 预期 |

| A06 | 用户使用方法但未验收/失败/中止 | 分别记录，不计成功复用，不删除失败成本 |
| A07 | 样本不足、不可比或缺失成本 | 显示未知与限制，不填零，不产生精确效果排名 |

| A13 | 新闻/播客检索失败或来源过期 | 不编造内容，说明日期/状态，可继续时间任务 |
| A14 | 用户删方法或撤销关联 | 任务与时间结果保留，引用有解释，无幽灵成功记录 |
| A15 | 恶意导入模板、HTML、危险 URL | 不执行、不越权、不扩大上下文；安全呈现或拒绝 |

| A17 | 构建后的交付目录使用新能力 | 必需文件齐全，核心流程与开发目录一致 |

### 16.1 验证方式

实施后先检查 package.json 和对应测试定义，确认目标与副作用，再选择验证：

~~~text
npm run verify:web
npm run verify:ui
npm run build
~~~

这些是当前仓库提供的相关命令，不是本次已执行或已通过的记录。按变更补充有价值的数据、权限、迁移与主流程测试；不要只写镜像实现的断言，也不为纯文案变更堆叠测试。

真实模型联调与自动化模拟分开报告。真实请求可能计费；沿用明确授权与项目测试入口，报告请求的配置模型、服务可观察证据和答案核验，禁止输出凭据或私人正文。不能用 mock、静态页面或 HTTP 成功码宣称完整模型能力已验证。

截图/录屏可证明页面状态，不能证明长期成长。测试失败应区分既有失败与本次引入；未运行、环境受限与未覆盖项写清楚。

## 17. 人工证据、上线与融资边界

用户决定把人工闭环证据持续累计，待工程阶段完成后集中实测。开发可以继续；不得将延期视为已经完成，也不因缺少长期研究而停下可独立完成的工程工作。

在真人证据台账中沿用/关联相关项：HE-13 技能迁移、HE-15 长期复用与习惯、HE-19 可比模型观察、HE-21 上下文建议、HE-22 反思、HE-23 资讯、HE-24 模型/费用/隐私。执行时核对条目现状，只补充必要证据要求，不覆盖旧记录。

首批实测可沿用资料初筛/核对场景与 8–12 人探索规模；这是建议样本，不是已招募或代表全民的证据。之后再扩展教师、职工等任务族，避免把不同任务混为一个成功率。

| 达成层次 | 可作出的结论 | 仍不能作出的结论 |
|---|---|---|
| 工程验证 | 指定版本的相关边界与流程通过实际检查 | 用户一定理解、长期留存或产品市场匹配 |
| 受控试用 | 小范围用户可体验指定功能与限制 | 已适合公开生产部署 |
| 人工验证 | 指定人群/场景出现质量、复用或迁移观察 | 对所有人有效、证明 AI 因果收益 |
| 公开上线 | 另行验证部署、安全、滥用控制、费用、支持与恢复 | 自动获得融资或社会改革成效 |

公开服务若缺少身份/访问控制、速率与预算限制、密钥隔离、数据恢复或故障监控，应单独列为真实上线阻塞项。先检查已有能力和部署方式，不能机械新增后台，也不能把本机监听成功叫作公开上线。

融资材料后续需要真实 cohort、留存、可复用方法质量、独立迁移、付费意愿/成交、模型及支持成本与隐私策略。本文不预设转化率、估值或融资承诺。
