## 1. 当前进度感

V2 已有相当完整的产品表达、18 个桌面/移动入口、领域命令与本地闭环，并积累了多轮验收记录。距 V3 的主要差距集中在：**从浏览器内演示/个人记录，变为有服务端所有权、真实来源、持久执行和外部结果证明的个人系统。** 不是所有东西从零开始，也不能把已有页面算成这个目标已经完成。

| 层级 | 当前可用的依据 | 距离 V3 的状态 |
|---|---|---|
| 思想与合同 | 时间主权、请求/责任、批准/执行/核验分离已写入 V2 | 继承，细化跨端和外部后果 |
| 表达与本地流程 | 18 路由、双主题、多视图和历史交互证据 | 可复用；真实数据/关键异常仍需重验 |
| 身份与发信 | 服务端账号、Resend 发送步骤已有历史记录 | 实收注册/重置仍缺完整证据 |
| 业务数据 | 按 owner 区分的浏览器存储；服务端业务 hook 为空 | P0 架构缺口，优先级最高 |
| 外部动作 | 接口形状和本地回执语义已有；S13 实际适配器不做真实动作 | P0 真实 provider 闭环缺口 |
| 运维 | 隧道历史可达；新增容器文件；最新并行文档描述 launchd | 现状发生变化，需固定环境重新验证 |
| 产品价值 | 有理念和外部资料，没有真实纵向用户试用证据 | 形成性研究待执行 |

不提供伪精确整体完成率。可跟踪的后续进度单位是 G0–G6 门禁与 A01–A43 P0 场景；一个场景没取得匹配层级证据就不变成完成。

## 5. 继承、扩展、暂缓、不做

- 继承：Personal Agency Layer、18 屏信息架构、瓷白/水墨 tokens、本人控制、半开时间区间、批准/执行/核验分离、检查点和保持静驻。
- 扩展：服务端权威与所有权、真实空态、任意数据时间模型、通用方案、持久 Operation/outbox、真实单 provider、注意力投递语义、删除与恢复。
- 暂缓：双人协商放 P1，持续授权和家庭/团队放 P2；先靠形成性用户价值决定扩展。
- 不做：重写产品为聊天机器人、自动填满日历、未经批准外发、默认移动共享会议、把私人偏好变成永久授权。

这套划分是新版本建议，不撤销 V2 已承诺但未验的功能。旧 `DELIVERY-MATRIX.md` 保留为独立交付分母；V3 以新增合同与真实证据补齐，不通过降低标准制造进度。
